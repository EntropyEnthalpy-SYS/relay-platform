# 套餐、钱包与订单

0.27.0 增加最小运营交易核心：套餐、单币种钱包、幂等资金流水、订单、钱包支付和退款。它是计费基础，不是完整商业系统。0.135.0 增加可选的套餐权益：付款的套餐流量和天数自动变成购买者的共享额度，见下文。之后又增加套餐的流量重置周期和自动补流量，同样属于套餐权益。

## 金额与币种

- 所有金额以人民币 **分** 保存（`i64`），固定币种 `CNY`；不使用浮点数。
- 套餐价格 `0..=1,000,000,000,000` 分；时长 1..3650 天；流量可选且必须为正。
- 钱包余额不得为负；每次变更与一条流水在同一 SQLite 事务中提交。
- 资金流水引用（`reference`）全局唯一；重复引用返回 409，事务回滚，不会重复入账。

## 礼品码

管理员可创建礼品码（6..32 位代码、金额、启用状态、时间窗口、可选最大兑换次数）。用户兑换时，金额直接进入钱包并生成一条 `credit` 流水，引用为 `gift:<CODE>:<用户ID>`；每个用户每个码只能兑换一次，重复兑换 409。兑换次数在事务内递增；已兑换的码不能删除，只能停用。礼品码不创建订单，也不发放套餐权益。

## 套餐

管理员可创建/编辑/删除套餐。普通用户只看到启用套餐；管理员看到全部。套餐字段：名称、说明、价格、时长、可选流量、启用状态，以及流量重置策略和可选的自动补流量（见下文）。删除已有订单的套餐会被拒绝，建议停用。

订单保存创建时的套餐快照（名称、金额、时长、流量、重置策略、自动补流量），后续改价或改策略不影响已创建订单。订单有类型 `kind`：`plan`（购买或续费套餐，旧订单都是这一类）或 `top_up`（自动补流量）。

## 钱包与订单

- 管理员可以按用户调整钱包：正数入账、负数扣款，必须提供唯一引用和说明；余额不足的扣款被拒绝。
- 用户可以创建订单（待支付），用钱包余额支付；支付在同一事务中扣余额、写 `purchase` 流水并标记订单已支付。
- 同一订单重复支付返回 409；零价套餐直接标记已支付且不写零金额流水。
- 管理员可以退款已支付订单：余额入账、写 `refund` 流水、标记已退款；重复退款返回 409。外部支付订单不能走钱包退款，必须由支付网关处理。
- 订单记录支付通道 `channel`（`wallet` 或 `external`）。钱包支付会作废该订单仍待支付的外部支付意图，之后到达的外部回调会被拒绝，避免双重支付。
- 用户只能查看自己的钱包/订单；系统管理员可查看全部订单并调整钱包。

**重要边界**：未开启可选功能 `plan-entitlements` 时，支付/退款只改变钱包和订单，不自动创建订阅、节点、规则或流量额度。

## 套餐权益（0.135.0，可选功能，默认关闭）

系统管理员在「可选功能」开启 `plan-entitlements` 后，订单变为已支付（钱包支付或外部回调）的同一事务内会给购买者发放权益：

- 每位用户一条权益记录（`entitlement:<user>`），绑定该用户的 user 范围共享额度。已有 user 额度会被沿用，原额度作为基础值；没有时自动创建额度包（预留粒度 4 MiB）。购买者仍有启用规则时额度无法创建，权益进入“等待额度”，付款照常完成；购买者停用规则并等节点确认后，可点“立即生效”，控制器也每 60 秒自动重试。
- 不重置流量的套餐：额度上限 = 基础值 + 未退款订单的流量；任一订单不限流量时为不限。续费叠加流量，并从当前到期时间顺延天数。重置流量的套餐见下一节。到期或全部退款后上限冻结为已承诺字节，并标记该额度不再发放新预留（节点归还未用预留也不会重新放出空间）；到期后续费从已用量重新开始。
- 退款扣回该订单的流量和天数，上限永不低于已承诺字节，已用流量不退回。外部通道订单仍不能在面板退款。
- 生效或等待中的权益所绑定的额度不能手动修改；已到期的额度可以由管理员调高，调高即重新开放。
- 开启前已支付的订单不补发。仍有生效或等待中的权益时不能关闭该功能。
- 设备数、限速和订阅有效期不由套餐控制。
- 接口：`GET /commerce/entitlement`（本人）、`GET /commerce/entitlements`（系统管理员）、`POST /commerce/entitlements/{user}/activate`（本人或系统管理员）。只接受登录会话，API 令牌会被拒绝。审计动作 `commerce.entitlement.grant|revoke|activate|expire`。

### 流量重置周期

套餐字段 `traffic_reset` 决定何时重新开始计算流量：

| 值 | 含义 |
| --- | --- |
| `"none"` | 默认。不重置，与 0.135.0 完全相同；没有此字段的旧套餐、旧订单按它处理 |
| `"billing"` | 跟随计费周期：从套餐生效起，每个已付费周期结束时重置。续费从当前到期时间顺延，所以边界是生效时间加上各订单天数的累计 |
| `{"every_days": N}` | 每 N 天（1..366）独立重置，从第一个周期的开始时间计算，与套餐时长无关 |

- 每个周期的流量是最近一笔未退款订单的套餐流量，未用完的不结转；续费只顺延到期时间，不叠加流量，新订单的流量从下一个周期起生效。退款扣回该订单的天数，当前周期的流量不变。
- 重置落在到期时间或之后时不再重置，到期按原规则冻结额度。到期后再买从购买时刻开始新的周期。
- 采用已有 user 额度时，原额度的上限不带入周期；周期从该额度已经确认的用量开始计算。
- 一个有效套餐只有一种重置策略。仍在有效期内的套餐与要购买的套餐策略不同（含 N 不同）时，创建订单返回 409，需等当前套餐到期后再买。此前已创建、之后才付款的这类订单会开始新的有效期：原套餐剩余的天数和流量作废，与到期后续费相同。管理员修改已有套餐的策略后，现有用户的续费订单使用新策略，因此要等当前套餐到期后才能续费。
- 控制器每 60 秒检查到期的周期；停机期间错过多个边界时只重置一次，进入当前周期。周期边界已过、而这次检查尚未运行时，额度不足的预留申请会先在同一事务中开始新周期，不会购买随即被清零的补流量。系统管理员可以对单个用户“立即重置流量”：从现在开始新周期，本周期补流量清零，到期时间不变；`every_days` 从此刻重新计天，`billing` 仍在下一个计费边界重置。重置不改写额度的累计账，只移动周期基线；周期开始时节点仍持有的预留计入新周期，原因和账本细节见 [BUDGETS.md](BUDGETS.md#套餐流量周期与自动补流量)。
- 用户的周期视图（`GET /commerce/entitlement` 的 `current_cycle`，面板「钱包与订单 → 我的套餐」）显示周期起止、下次重置、本周期流量（含补流量）、已用、预留中、剩余、补流量次数与上限、上次未能补流量的原因。客户端订阅的 `Subscription-Userinfo` 也按当前周期报告已用和总量。

### 自动补流量

套餐字段 `top_up`：`{"bytes": 每次补充字节, "price_cents": 每次价格（分，0..1,000,000,000,000）, "max_per_cycle": 每周期最多次数（1..1000）}`，可选。只能用于设置了流量且 `traffic_reset` 不是 `none` 的套餐，否则 400。

- 用户需要开启“用完自动补流量”（`auto_top_up`），本人或系统管理员可以切换，默认关闭。
- 节点申请预留时，如果本周期剩余可分配不足一份完整预留，控制器在同一事务中补流量：从钱包扣款并写一条 `purchase` 流水（引用 `top_up:<用户>:<周期序号>:<次数>`），创建一笔已支付、`kind` 为 `top_up` 的订单（`traffic_bytes` 为补充量、`duration_days` 为 0），本周期上限提高 `bytes`，再发放预留。价格为 0 时不写零金额流水。
- 并发申请、重放请求和控制器重启都不会重复扣款：分配事务串行执行，重放同一请求直接返回原预留，流水引用唯一。
- 补流量不延长到期时间，下次重置时清零；补流量订单不能用订单退款（409），需要时由管理员调整钱包。
- 不能补流量时不扣款，记录原因：`not_configured`（套餐未配置）、`switched_off`（用户未开启）、`cap_reached`（本周期已达上限）、`insufficient_balance`（余额不足）。剩余的少量字节照常发放，额度用尽后触发已有的“共享额度已用尽”告警，告警说明原因。同一原因只记录一次；之后每次申请只读检查，余额补足或开启开关后下一次申请即可补流量。切换开关会清除旧原因。
- 不重置流量的套餐不会自动补流量，耗尽时也不记录原因，与之前相同。
- 审计动作：`commerce.entitlement.reset`（`manual` 区分手动与到期）、`commerce.entitlement.auto_top_up`、`commerce.top_up`、`commerce.top_up.fail`。

## API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET/POST | `/commerce/gift-codes` | 管理员礼品码列表/创建；普通用户 403 |
| PUT/DELETE | `/commerce/gift-codes/{id}` | 管理员编辑/删除；已兑换删除 409 |
| POST | `/commerce/gift-codes/redeem` | 用户兑换 `{code}`，直接入钱包 |
| GET/POST | `/commerce/coupons` | 管理员优惠码列表/创建；普通用户 403 |
| PUT/DELETE | `/commerce/coupons/{id}` | 管理员编辑/删除；已有使用时删除 409 |
| GET/POST | `/commerce/plans` | 列表/创建套餐（写仅系统管理员）；可选 `traffic_reset`、`top_up` |
| PUT/DELETE | `/commerce/plans/{id}` | 编辑/删除（仅系统管理员） |
| GET | `/commerce/wallet` | 自己的钱包与流水（含补流量扣款） |
| GET | `/commerce/entitlement` | 自己的套餐权益与 `current_cycle` |
| GET | `/commerce/entitlements` | 系统管理员：全部权益与周期 |
| POST | `/commerce/entitlements/{user}/activate` | 本人或系统管理员：等待额度的套餐立即生效 |
| PUT | `/commerce/entitlements/{user}/auto-top-up` | 本人或系统管理员：`{enabled}` 切换“用完自动补流量” |
| POST | `/commerce/entitlements/{user}/reset` | 系统管理员：立即重置该用户本周期流量 |
| POST | `/commerce/wallets/{user}/adjust` | 管理员调整 `{delta_cents,reference,description}` |
| GET/POST | `/commerce/orders` | 自己的订单/创建订单 `{plan_id}`；管理员看全部；`kind` 为 `plan` 或 `top_up` |
| POST | `/commerce/orders/{id}/pay` | 钱包支付 |
| POST | `/commerce/orders/{id}/refund` | 管理员退款（仅钱包支付的套餐订单；补流量订单 409） |
| POST | `/commerce/orders/{id}/payment` | 创建/复用待支付外部支付意图 |
| GET/PUT | `/commerce/webhook` | 管理员查看/配置 HMAC 回调和启用状态 |
| POST | `/commerce/payments/callback` | 网关回调（无登录，HMAC 验证原始请求体） |

除公开回调外，所有 `/commerce/*` 仅接受登录会话，API 令牌访问返回 403；面板“钱包与订单”页提供套餐购买、钱包/外部支付、退款、套餐管理、钱包调整和回调密钥配置（管理员）。

外部回调请求体示例：

```json
{"payment_id":"…","status":"paid","external_id":"gateway-123","amount_cents":5000}
```

`X-Relay-Signature` 是原始 JSON 字节的 HMAC-SHA256 十六进制（可带 `sha256=` 前缀）。同一支付/状态重复回调返回 `duplicate:true`；金额不符、签名错误、支付意图已被钱包支付作废或状态冲突返回 4xx。回调只改变订单/支付状态，不给钱包入账。

## 验证与限制

- Store 测试覆盖启用/停用套餐可见性、非管理员建套餐 403、钱包入账/重复引用 409/负余额拒绝、订单快照、支付扣款、重复支付 409、用户退款 403、管理员退款、重复退款 409、最终余额和流水；优惠码覆盖 10% 折扣、原价/折扣/最终金额、使用次数上限、停用后拒绝、按折后金额支付与退款。
- HTTP 测试覆盖创建套餐、买家 403 创建套餐、管理员调整钱包、买家创建/支付订单、钱包余额、管理员退款和最终余额。
- 外部支付测试覆盖 HMAC 签名、错误签名 401、支付成功、重复回调幂等、订单通道为 external、钱包不变和外部订单钱包退款 409。
- 礼品码测试覆盖管理员创建、非管理员 403、兑换入账、每用户一次、全局次数上限、停用/过期、删除已兑换 409 和 HTTP 流程。
- 流量周期测试（`tests/traffic_cycles.rs`）通过真实预留交换和两个 Agent 数据库覆盖：计费边界与每 N 天重置、停机错过多个边界只重置一次、重启后不重复重置、边界已过而检查未运行时先重置而不补流量、未用流量不结转、跨周期持有的预留计入新周期、立即重置及权限、并发申请只补一次且重放与重启不重复扣款、次数上限、余额不足不扣款、开关关闭、未配置、补流量在重置时清零且不改到期时间、`none` 与之前一致，以及 HTTP 路由的角色与 API 令牌限制。`tests/subscriptions.rs` 覆盖订阅头按周期报告。`scripts/test_web_traffic_cycles.cjs` 检查面板发出的请求体。
- 未实现具体支付网关适配/退款 API、佣金、税、发票、工单（另见 TICKETS.md）、自动续费、套餐限速与设备数、退款对账导出、异步支付状态、优惠码定时窗口 UI 和浏览器点击验收；流量周期不含按倍率扣量、手动购买流量包、补流量退款和续费价格模式。完整运营交易仍未完成。
