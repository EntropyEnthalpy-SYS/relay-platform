# 套餐、钱包与订单

0.27.0 增加最小运营交易核心：套餐、单币种钱包、幂等资金流水、订单、钱包支付和退款。它是计费基础，不是完整商业系统；套餐权益尚未自动发放到转发规则或订阅。

## 金额与币种

- 所有金额以人民币 **分** 保存（`i64`），固定币种 `CNY`；不使用浮点数。
- 套餐价格 `0..=1,000,000,000,000` 分；时长 1..3650 天；流量可选且必须为正。
- 钱包余额不得为负；每次变更与一条流水在同一 SQLite 事务中提交。
- 资金流水引用（`reference`）全局唯一；重复引用返回 409，事务回滚，不会重复入账。

## 礼品码

管理员可创建礼品码（6..32 位代码、金额、启用状态、时间窗口、可选最大兑换次数）。用户兑换时，金额直接进入钱包并生成一条 `credit` 流水，引用为 `gift:<CODE>:<用户ID>`；每个用户每个码只能兑换一次，重复兑换 409。兑换次数在事务内递增；已兑换的码不能删除，只能停用。礼品码不创建订单，也不发放套餐权益。

## 套餐

管理员可创建/编辑/删除套餐。普通用户只看到启用套餐；管理员看到全部。套餐字段：名称、说明、价格、时长、可选流量、启用状态。删除已有订单的套餐会被拒绝，建议停用。

订单保存创建时的套餐快照（名称、金额、时长、流量），后续改价不影响已创建订单。

## 钱包与订单

- 管理员可以按用户调整钱包：正数入账、负数扣款，必须提供唯一引用和说明；余额不足的扣款被拒绝。
- 用户可以创建订单（待支付），用钱包余额支付；支付在同一事务中扣余额、写 `purchase` 流水并标记订单已支付。
- 同一订单重复支付返回 409；零价套餐直接标记已支付且不写零金额流水。
- 管理员可以退款已支付订单：余额入账、写 `refund` 流水、标记已退款；重复退款返回 409。外部支付订单不能走钱包退款，必须由支付网关处理。
- 订单记录支付通道 `channel`（`wallet` 或 `external`）。钱包支付会作废该订单仍待支付的外部支付意图，之后到达的外部回调会被拒绝，避免双重支付。
- 用户只能查看自己的钱包/订单；系统管理员可查看全部订单并调整钱包。

**重要边界**：支付/退款只改变钱包和订单，不自动创建订阅、节点、规则或流量额度。套餐权益执行（到期、限速、配额、设备数）仍是后续工作。

## API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET/POST | `/commerce/gift-codes` | 管理员礼品码列表/创建；普通用户 403 |
| PUT/DELETE | `/commerce/gift-codes/{id}` | 管理员编辑/删除；已兑换删除 409 |
| POST | `/commerce/gift-codes/redeem` | 用户兑换 `{code}`，直接入钱包 |
| GET/POST | `/commerce/coupons` | 管理员优惠码列表/创建；普通用户 403 |
| PUT/DELETE | `/commerce/coupons/{id}` | 管理员编辑/删除；已有使用时删除 409 |
| GET/POST | `/commerce/plans` | 列表/创建套餐（写仅系统管理员） |
| PUT/DELETE | `/commerce/plans/{id}` | 编辑/删除（仅系统管理员） |
| GET | `/commerce/wallet` | 自己的钱包与流水 |
| POST | `/commerce/wallets/{user}/adjust` | 管理员调整 `{delta_cents,reference,description}` |
| GET/POST | `/commerce/orders` | 自己的订单/创建订单 `{plan_id}`；管理员看全部 |
| POST | `/commerce/orders/{id}/pay` | 钱包支付 |
| POST | `/commerce/orders/{id}/refund` | 管理员退款（仅钱包支付） |
| POST | `/commerce/orders/{id}/payment` | 创建/复用待支付外部支付意图 |
| GET/PUT | `/commerce/webhook` | 管理员查看/配置 HMAC 回调和启用状态 |
| POST | `/commerce/payments/callback` | 网关回调（无登录，HMAC 验证原始请求体） |

除公开回调外，所有 `/commerce/*` 仅接受登录会话，API 令牌访问返回 403；面板“钱包与订单”页提供套餐购买、钱包/外部支付、退款、套餐管理、钱包调整和回调密钥配置（管理员）。

外部回调请求体示例：

```json
{"payment_id":"…","status":"paid","external_id":"gateway-123","amount_cents":5000}
```

`X-Relay-Signature` 是原始 JSON 字节的 HMAC-SHA256 十六进制（可带 `sha256=` 前缀）。同一支付/状态重复回调返回 `duplicate:true`；金额不符、签名错误、支付意图已被钱包支付作废或状态冲突返回 4xx。回调只改变订单/支付状态，不给钱包入账。

## 验证与限制

- Store 测试覆盖启用/停用套餐可见性、非管理员建套餐 403、钱包入账/重复引用 409/负余额拒绝、订单快照、支付扣款、重复支付 409、用户退款 403、管理员退款、重复退款 409、最终余额和流水；优惠码覆盖 10% 折扣、原价/折扣/最终金额、使用次数上限、停用后拒绝、按折后金额支付与退款。
- HTTP 测试覆盖创建套餐、买家 403 创建套餐、管理员调整钱包、买家创建/支付订单、钱包余额、管理员退款和最终余额。
- 外部支付测试覆盖 HMAC 签名、错误签名 401、支付成功、重复回调幂等、订单通道为 external、钱包不变和外部订单钱包退款 409。
- 礼品码测试覆盖管理员创建、非管理员 403、兑换入账、每用户一次、全局次数上限、停用/过期、删除已兑换 409 和 HTTP 流程。
- 未实现具体支付网关适配/退款 API、佣金、税、发票、工单（另见 TICKETS.md）、账单周期、套餐权益执行、退款对账导出、异步支付状态、优惠码定时窗口 UI 和浏览器点击验收。完整运营交易仍未完成。
