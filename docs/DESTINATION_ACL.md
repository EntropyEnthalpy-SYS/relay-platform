# 目的地访问控制

0.34.0 为规则增加目的地允许/拒绝列表，补充分流与访问控制的网络层基础。

## 规则字段

```json
{
  "allow_destinations": ["*.example.com", "10.0.0.0/8", "203.0.113.7"],
  "deny_destinations": ["secret.example.com", "10.9.0.0/16"]
}
```

- 支持：`*`、IPv4/IPv6 地址、CIDR、精确域名、`*.example.com`/`.example.com` 后缀。
- 不接受端口、URL、协议前缀或路径；非法模式在配置校验阶段明确拒绝。域名大小写不敏感，末尾点被忽略。
- 拒绝优先；允许列表为空表示“除拒绝外全部允许”，非空则是白名单。
- 匹配同时检查原始域名（代理目的地/域名目标）和解析后的所有 IP；域名允许但 IP 被拒绝时仍拒绝。解析出多个地址时逐地址检查。
- 适用于固定 TCP/UDP 目标、Shadowsocks、SOCKS5 TCP、HTTP CONNECT、多路径路径和 UDP 目标；预热连接也不会绕过。
- 记录仍在规则 JSON 中，schema v5 和恢复日志格式 4 不变。

## 界面与 API

规则编辑器“高级”区域增加两个多行输入；API 直接使用上述字段。普通规则 JSON 省略空列表，保持旧配置兼容。面板的“功能进度”列出目的地 ACL。

## 验证与限制

- 单元测试覆盖后缀/精确域名、CIDR/IP、拒绝优先、空允许列表和非法模式。
- Engine 测试覆盖拒绝时目标 listener 完全不会收到连接，以及允许 CIDR 时真实 TCP 回显；模式在固定目标路径统一执行。
- 未实现端口范围、GeoIP/ASN、协议组合、域名正则、规则优先级/多规则链、DNS 解析前后语义分离、每用户策略、真实 Cloudflare/域名污染测试和浏览器点击验收；模块 18 仍为部分实现。
