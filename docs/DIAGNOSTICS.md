# 计量、补额与同步诊断

0.11.0 为真实业务计量和节点同步增加进程内计时，并修复补额通知竞态、合并同一同步回复的本地持久化事务。统计通过现有节点和控制器 API 提供，不承担流量计费、配额授权或退款职责。

0.12.0 增加 `stats.multipath`：逻辑会话和物理子流、复制/重传负载、窗口峰值及逐槽位发送量。具体口径见 [MULTIPATH.md](MULTIPATH.md)。槽位按规则内路径顺序解释，跨规则累计的同号槽位不代表同一网卡；传输层额外负载不能直接用作业务账单或网卡总字节数。

有序停止在引擎任务结束后至少发送一次最终同步，即使没有待确认用量或预留。最终回报保留配置应用错误，避免把停止误报为配置成功。回报仍受两秒清理期限约束；控制器离线或进程突然退出时，不保证控制器已收到零活跃状态。停用及拓扑改向的排空检查同时考虑聚合逻辑会话和物理子流。

## 补额等待与持久化

TCP/UDP 业务仍先持久化接纳字节，再向目标写出；全局额度仍按现有 quantum 分配、累计消费、幂等确认和有序归还。本轮没有提高预留粒度、改变补额阈值、删除恢复日志或降低同步落盘要求。

旧等待顺序存在如下竞态：计量返回“等待额度”之后，补额事务已经提交并广播通知，但业务尚未创建等待对象。通知不会作为下一位等待者的许可保留，于是业务继续等到最多 50 ms 的轮询窗口。新实现先创建等待对象，再提交计量请求；即使额度在等待对象首次被轮询之前到达，也能观察到更新。剩余的 50 ms 重试仍用于无新通知时重新检查状态和超时，不能把它当作所有停顿都已消除。

回归测试在 0.10.0 实现上稳定复现上述遗漏，在新实现上验证多个等待者都收到同一次已提交更新；新创建的观察者不会消费旧通知。这证明该竞态修复，不直接证明整个共享额度性能问题已经解决。

Agent 接收一次同步回复时，用量序号确认、预留写入、取消请求及消费确认现在在同一个本地事务内完成。任一后续字段非法或写入失败，都回滚整份回复；提交成功并释放数据库锁后才唤醒业务。重复合法回复继续幂等。正常同步与停止结算采用相同实现，预留请求与控制器回执的身份检查保留。

## 节点统计

`GET /api/v1/nodes` 的 `stats.meter` 是最近一次 Agent 回报。权限与节点列表相同：普通用户只能读取自己可见租户的节点。字段不存在表示节点未提供诊断，不能按零故障或零等待推断。界面“节点管理 → 运行诊断”显示采样时间，并明确标出没有近期回报的旧数据。

| 字段 | 含义 |
| --- | --- |
| admission_batches | 非空计量批次耗时；从提交到阻塞线程池到得到数据库结果，包含线程池调度、锁等待、SQL 与持久化 |
| admission_requests | 已处理的计量请求数；包含重试、被额度阻挡和被规则拒绝的请求 |
| failed_batches | 计量数据库或任务失败的批次数；正常的配额不足不属于此类错误 |
| budget_wait | 业务得知额度不足之后，每次实际等待片段的耗时 |
| budget_waiting | 采样时正在等待通知或重试定时器的方向/会话数；不含正在执行计量查询者 |
| budget_timeouts | 额度等待达到该规则截止时间而终止本次接纳的次数 |

每个耗时对象采用 `{samples,total_us,max_us}`，单位为微秒。`samples` 是已结束片段数；平均值可用 total/samples 计算，零样本没有平均值。TCP 两个方向分别计量；同一应用块可能多次等待，多个连接的等待时间可以重叠，因此累计等待秒数可以超过程序运行秒数。取消中的等待片段也在退出时记录，不把取消全部算成等待超时。

纯屏障批次不计入 admission_batches。数据库阶段不是纯 `fsync` 耗时，也不包含调用者进入计量消息队列前的所有等待。空闲后仍保留统计；进程重启归零，故障退出前未上报的诊断样本可能丢失。业务账本仍独立持久保存。

## 控制器统计

`GET /api/v1/control/metrics` 继续仅允许系统管理员，新增以下三个耗时对象；“恢复保护 → 节点同步”页面展示采样数、平均与最大值。

| 字段 | 起止范围 |
| --- | --- |
| queue_time | 请求成功进入有界队列至批次准备完成，包含等待前一批次及合并窗口 |
| storage_batch_time | 批次提交到阻塞线程池至返回存储结果，包含调度、数据库锁、SQL、恢复日志与进度清单提交 |
| request_time | 单个请求进入队列至所在批次存储结果返回 |

这些时间不包含 HTTP 响应传输、Agent 收包和 Agent 本地事务，也不能仅靠它们证明磁盘或网络是唯一瓶颈。存储失败的已处理请求也计入耗时；队列满导致的 429 由原有 `queue_full_rejections` 统计，不进入上述处理耗时。已取消且尚未执行的请求不算完成。

`processed_requests` 仍按已完成持久化批次计数（包含该批次中被独立校验拒绝的请求）；发生整批存储错误时只增加 failed_batches。因此 request_time.samples 可能大于 processed_requests。storage_batch_time.samples 包含成功与失败存储批次。

所有统计为多个原子计数的近似并发快照，不是一份计费事务。短暂并发读可能在字段间观察到不同采样边界；没有保存历史分位数，最大值不等于 P95。

## 验证与使用边界

新增测试覆盖丢失唤醒、多等待者、后续无关观察者、非法回执后的全事务回滚、真实数据库写失败、合法重试和不重复授信。既有两 Agent TCP 测试新增 API 观测断言，验证正常转发、真实等待、耗尽超时和有序停止后的零等待。控制器指标仍执行认证与管理员权限测试。

`scripts/bench_budget.py` 会保存 `node_meter_metrics` 和完整控制器统计。比较旧版时，未提供的节点统计记为 null。脚本仍核对每个应用字节、所有节点账本、控制器账本、预算消费和停止后未使用预留归零。具体版本、原始样本和限制见 [VALIDATION.md](VALIDATION.md)。

数据库 schema v4、请求身份和恢复日志格式保持不变。新 Agent 在 stats 中发送 meter 字段，因此应先升级控制器再升级 Agent；旧控制器会严格拒绝未知字段。本轮没有完成历史监控、系统资源采集、分布式公平性、控制面高可用或完整性能验收。

## 节点执行租约状态

0.13.0 的 GET /api/v1/nodes 新增 lease，节点表和诊断页面展示 policy、generation、holder_run_id、active、remaining_ms、recovery_wait_ms。无策略表示离线模式；active 是控制器的授权保留状态，进程突然退出后也可能维持到截止时间。新持有者会清除旧回执/诊断，直到当前 Agent 重新上报。运行令牌与哈希不向页面返回；租约过期不代表未使用预留已经归还。见 [NODE_LEASES.md](NODE_LEASES.md)。

## 0.14.0 原状态恢复诊断

节点最近一次 stats.budget_recovery 可包含恢复 run_id、完成时间 at_ms、validated_grants、recovered_pending_grants、cancelled_requests、open_grants。这些计数来自本次进程启用监听前的完整恢复；正常停止的最后一次心跳保留该记录。open_grants 是当时仍开放且有余额的预留数量，不是余额字节数，也不会随之后业务变化更新。没有字段表示本次进程未报告这类恢复，不能推断以前从未崩溃。

额度页面提供只读预留明细，按 grant_id 每页最多 100 条，显示所属节点、预算运行、已分配、控制器确认消费、尚占用量和当前节点租约。页面说明尚占用量包括未上报消费；租约状态属于该节点现在的持有者，不证明每条旧预留仍由当前 run_id 使用。多页读取不是固定快照，不应当作结算凭据。API 权限测试已覆盖，浏览器视觉和点击仍未验收。

## 0.15.0 节点许可与资料

节点列表把资料、运行许可、控制连接、租约和配置回执分别显示。profile.revision 只表示资料版本；不会改变 desired_revision/applied_revision。lifecycle=active 表示允许领取且未到期，不证明 Agent 已启动；暂停后仍可能有尚未结束的授权窗口。到期时间在前端按浏览器本地时区显示，API 持久保存 Unix 毫秒时间戳。

节点筛选下的在线数/连接数只覆盖筛选结果，近期上报负载仍标明为所有可见节点的最近 2,000 个计量周期。成本按原币种和周期展示，不跨币种相加或推断线路性价比。管理界面已接入资料、筛选和批量结果；浏览器视觉/点击仍待验收。

## 0.16.0 节点凭据状态

节点凭据详情读取当前版本、待执行任务、请求时间和最后完成回执，不展示秘密或哈希。待执行表示尚未确认换钥完成，可能是节点离线、暂停、未升级或正在重试；需结合节点控制回报与 Agent 日志判断，不能等同于凭据已被撤销。明确记录 `node.credential.request` 与 `node.credential.rotate` 两类审计。0.17.0 的单节点紧急撤销与替换见下节，批量身份替换仍未完成。

## 0.17.0 节点身份状态

节点列表的 `credential_phase` 和身份详情区分未注册、有效、已撤销和等待替换注册。注册令牌到期不自动变更阶段，应同时查看 `replacement.expires_at_ms`；注册完成时间保留在 `enrolled_at_ms`。`blocked_quota_periods` 列出阻止新实例领取租约的旧规则周期，不表示旧消费已准确核清。

审计新增 `node.identity.revoke` 和 `node.identity.replacement`，记录操作者、原因、修订、期限与离线停止确认，不保存令牌明文或哈希。身份、租约、配置回执、业务健康分别查看，替换注册成功不等于已经开放转发。详情见 [NODE_IDENTITY.md](NODE_IDENTITY.md)。
