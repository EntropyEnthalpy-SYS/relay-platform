# 节点凭据轮换

0.16.0 增加节点控制 API 凭据的常规轮换。管理员只发起任务，Agent 自行生成 256 位随机新凭据，先写入私有状态库，再提交控制器。页面、状态 API、审计和验收报告均不展示凭据或凭据哈希。控制器只保存当前哈希及退役哈希标记；这些标记随恢复日志持久化。

本功能不改变规则修订、节点资料、租约运行编号或预留归属。已有 TCP/UDP 可以继续使用同一运行实例；租约仍独立续期，轮换失败不能延长业务授权窗口。它是正常持有节点状态时的换钥流程，不是已经被入侵或丢失全部状态后的身份替换方案。

## 操作与状态

在“节点总览 → 节点身份”查看当前凭据版本、待执行任务和上次完成时间。系统管理员可以操作所有节点；租户管理员仅操作本租户节点；只读用户仅查看本租户状态。未注册节点不能轮换。

| 方法 | API | 内容 |
| --- | --- | --- |
| GET | `/api/v1/nodes/{node}/credential` | `revision`、可空 `pending`、可空 `last_rotation` |
| POST | `/api/v1/nodes/{node}/credential/rotate` | 管理会话；`{"expected_revision":1}` 发起任务 |
| POST | `/api/v1/agent/credential/rotate` | 节点凭据；`{request_id,expected_revision,credential,lease}` 提交新凭据 |

注册后的初始凭据版本为 1，旧版已注册节点也按 1 读取；未注册为 0。任务包含 `id`、`expected_revision`、`requested_at_ms`、`requested_by`。同一节点同时最多一个待执行任务；重复发起、过期版本或未注册节点返回 409。返回的新任务不表示节点已经完成换钥。只读写操作为 403，不可见节点为 404，未认证为 401。

Agent 在成功同步回复的可选 `credential_rotation` 中收到任务。离线节点的任务持久保留，恢复连接后继续处理。暂停或到期的严格节点需要先恢复运行资格；任务不会绕过这些限制。旧 Agent 会忽略任务，管理员需要先升级，不能把“已发起”当成旧节点已经换钥。

成功提交返回 `{id,revision,completed_at_ms}`，凭据版本加 1，待执行任务清空。页面按刷新时读到的控制器状态展示结果。任务目前没有取消、超时自动撤销、批量发起或管理员直接指定密钥的接口。

## 持久化与并发合同

1. Agent 将当前凭据、新候选和任务编号一起落盘。候选持久化失败时，不发送任何换钥请求。
2. 严格节点提交时必须提供仍有效的当前执行租约证明。持有旧节点凭据但没有租约的复制实例不能抢先提交。离线策略没有跨实例所有权保护，持有该节点凭据和状态的实例仍可能竞争。
3. 控制器在同一事务中校验当前凭据、任务、版本和租约，然后退役旧哈希、切换新哈希、保存完成回执并写审计。任一步失败都回滚；开启恢复日志时沿用现有持久化屏障和失败后拒绝写入规则。
4. 提交后旧凭据不能再通过节点认证。同步批次、租约、预留恢复和分页对账均在各自事务内验证当前凭据；已经在切换之前完成事务的请求仍可能稍后送达回复。
5. Agent 收到对应回执后持久化新版本，移除旧凭据和候选标记。其租约续期、同步、对账和预算恢复共享同一凭据状态。旧请求遇到 401 时，只使用本地已经持久化的候选或新确认凭据重试一次；如果又有更新发生，退回正常有界重试。不会无限尝试，也不会延长租约截止时间。

退役凭据不能再次成为任何节点的新凭据，包括通过新节点注册。控制器不会接受任意管理员填写的新密钥。只有任务指定的新版本可以推进；两个并发候选只有一个成功。

## 中断和恢复

- **控制器提交前终止 Agent：** 本地仍有旧凭据和持久化候选，控制器仍保留待执行任务。重启后按正常租约规则取得所有权，使用同一候选继续。
- **控制器已提交但回复丢失：** 旧凭据返回 401，本地候选可以认证。携带当前新凭据和原任务重试，控制器返回相同回执，不增加版本、不重新写入，也不影响后续已排队任务。这种只读确认不重新要求旧租约有效。
- **新凭据已经确认落盘：** 后续请求仅使用新凭据，不保留旧凭据回退路径。
- **控制器旧备份加完整恢复日志：** 恢复任务、当前哈希、退役标记和完成回执。须先停止控制器，使用正常恢复 CLI；原始快照回退或同时丢失数据库与日志没有新鲜度保证。
- **Agent 状态太旧或丢失：** 旧注册令牌不能重新绑定新凭据。不能通过删库、旧备份或原令牌重新注册推定身份可恢复。0.17.0 提供单独的[身份撤销与替换](NODE_IDENTITY.md)，需要新令牌和全新私有状态，未知消费不会自动恢复。

换钥不撤销已被复制的整机控制权，也不清除未知预算消费。若非协作式实例仍控制着机器，API 换钥不能强制其关闭系统套接字。严格节点的合作式执行租约边界继续按 [NODE_LEASES.md](NODE_LEASES.md) 生效。

## 升级和验收

先升级控制器，再升级 Agent，之后发起任务。数据库 schema 仍为 v4，但完成轮换后不能据此推定可以降级：旧 Agent 不理解未完成候选，旧控制器不执行退役检查。备份应包括最新节点状态，以及控制器数据库、恢复日志和 head 清单；不要将私有状态库加入源码包。

测试覆盖租户权限、版本冲突、严格所有权、候选重用拒绝、并发唯一胜出、存储失败回滚、重复确认、真实 TCP/UDP、旧凭据续租竞态、提交前后终止与旧备份重放。独立 CLI 入口为：

```sh
python3 scripts/check_credentials.py --binary target/release/relay --output docs/credentials-smoke.json
```

界面源码已接入；0.17.0 的单节点紧急撤销与替换另见 NODE_IDENTITY.md。浏览器视觉与点击、Linux/WAN、真实断电、批量节点替换和完整身份生命周期继续作为未完成项保留。当前验证结果以 [VALIDATION.md](VALIDATION.md) 为准。
