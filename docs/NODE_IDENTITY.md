# 节点身份撤销与替换

0.17.0 支持撤销现有节点身份，并用限时一次性注册令牌在全新的 Agent 私有状态目录重新注册。节点 ID、资料、转发配置与控制器已经确认的账本保留。原状态完整且只需要换钥时，继续使用 [常规轮换](NODE_CREDENTIALS.md)。

这是一套单控制器、协作式 Agent 的身份管理流程。撤销立即使旧凭据无法再通过控制器认证，但不能收回已经发出的执行窗口。严格节点在收到认证失败或自身授权期限结束后停止；新实例等待旧窗口结束。被控制的操作系统、不遵守租约的程序和离线策略实例不能靠控制器 API 强制关机。

## 操作步骤

1. 先升级控制器到 0.17.0，再准备同版 Agent。打开“节点管理 → 节点身份”，检查身份版本、租约策略和当前状态。
2. 提交撤销原因。控制器在同一事务中退役旧凭据及当前注册令牌，取消待执行轮换、撤销旧租约持有者并递增代数，保存操作回执和审计。旧转发配置与已知用量不清零。
3. 严格节点保留原 TTL。离线策略节点必须先由操作者在控制器外停止所有原实例和复制品，再明确确认这件事，选择 5～120 秒严格策略；页面默认 30 秒。平台记录确认，不能替操作者证明远端已经停止。
4. 签发限时替换令牌。页面用浏览器密码学随机源生成 256 位令牌，在这次结果中显示；控制器只保存哈希。令牌有效期为 1～86400 秒，默认页面 600 秒。应保存为权限 0600 的文件；关闭结果页面后不能从控制器取回明文，可重新签发并使上一令牌失效。
5. 使用**全新的私有状态目录**启动替换 Agent，沿用节点 ID。不要覆盖旧状态，也不要把新令牌指向含旧凭据的状态目录：已有凭据优先，旧状态不会被新令牌自动重绑。旧状态保留用于核对未知消费。
6. 等待注册、执行租约、配置应用与实际业务分别就绪。注册成功只说明身份绑定完成。若旧配额周期被保护，按下节先停用受影响规则或显式选择新周期，再等待接管。

```sh
./target/release/relay agent \
  --controller https://控制器地址 \
  --node-id 原节点ID \
  --enrollment-token-file /私有目录/replacement.secret \
  --state /私有目录/全新替换实例
```

控制器 URL 的 TLS 配置遵循现有部署约定。示例路径需要替换成实际私有目录。此版本没有批量替换或自动迁移节点本地证书、配置外部文件的流程。

## 状态和接口

状态接口为 `GET /api/v1/nodes/{id}/credential`。`phase` 为 `not_enrolled`、`active`、`revoked` 或 `replacement_pending`；保留 `revision`、`pending` 和 `last_rotation`，新增可空的 `revocation`、`replacement` 及 `blocked_quota_periods`。节点列表提供 `credential_phase`，与在线心跳、资料启停状态分别展示。

| 请求 | 管理会话 JSON 字段 | 成功结果 |
| --- | --- | --- |
| `POST /api/v1/nodes/{id}/credential/revoke` | `operation_id`、`expected_revision`、`reason` | 版本加 1，状态为 `revoked` |
| `POST /api/v1/nodes/{id}/credential/replace` | `operation_id`、`expected_revision`、`enrollment_token`、`valid_for_seconds`；可选 `offline_stop_attested`、`lease_policy` | 版本加 1，状态为 `replacement_pending` |
| `POST /api/v1/agent/enroll` | `node_id`、`enrollment_token`、`credential`、`identity_revision_supported:true` | `{enrolled:true,credential_revision}`；状态变为 `active`，版本保持 |

`operation_id` 采用现有标识符限制，可使用 UUID；`reason` 必须非空、至多 512 个 UTF-8 字节且没有控制字符。替换令牌为 64 位十六进制字符串；已有严格策略不能在替换时修改。系统管理员可操作全部节点，租户管理员限本租户；只读用户可以查看状态，不能修改。管理 API 不返回节点凭据、注册令牌或其哈希。

常见版本流程为：首次注册 `1` → 撤销 `2` → 签发 `3` → 注册仍为 `3` → 常规轮换 `4`。重新签发也递增版本，过期本身不会自动递增。未注册身份亦可撤销，不能推定所有节点都从版本 1 开始操作。

令牌有效期沿用控制器策略时钟：同一进程按单调经过时间和观察到的墙上时间向前推进，重启后依赖正确系统时间。错误系统时间或任意快照回退不在有效期保证内；重签或撤销产生持久退役标记，与单纯等待过期分别处理。

同一 `operation_id`、操作类型、操作者和请求内容可安全重试。控制器只保留请求摘要，精确重放返回**当前身份状态**，不会重新执行原操作。例如原撤销请求在新节点已经接管后重试，不会撤销新身份；原签发请求在后续签发完成后重试，不会恢复旧令牌或延长期限。同一编号换内容、换操作者或换操作类型返回 409。重试时必须保留原请求，包括同一令牌。

| 情况 | 状态码 |
| --- | --- |
| 旧节点凭据、无效或已消费的注册令牌 | 401 |
| 只读管理角色修改身份 | 403 |
| 不可见或不存在节点 | 404 |
| 过期修订、操作编号冲突、复用已记录密钥、未经撤销签发 | 409 |
| 匹配的替换注册令牌已经到期 | 410 |
| 旧窗口尚未结束、旧配额周期仍启用 | 423，租约领取继续等待 |
| 替换注册客户端没有声明版本能力 | 426，不消费令牌 |

首次注册仍接受没有能力字段的旧客户端。替换注册要求能力字段；Agent 将返回的实际凭据版本落盘，不能将其重置成 1。注册提交后响应丢失时，使用已持久化的同一新候选可确认原结果，不能生成另一个凭据重复绑定。

## 执行窗口与拓扑

撤销后的控制器立即拒绝旧凭据的同步、对账、租约领取/续期/释放、预算恢复及常规轮换请求。撤销之前已提交的请求仍可能稍后返回；它们代表之前获准的窗口和预留。

撤销清除旧持有者，同时保存它已获准窗口的剩余时间作为接替等待期。状态或审计持久化失败时，数据库和内存截止期均保持原状态。新实例可以在等待期注册，但不能提前取得执行权，也不能提前建立本地预算运行。控制器冷启动继续采用完整 TTL 的保守隔离，不因重启而缩短等待。

拓扑排空判断不再将“身份未注册”直接等同于“旧业务已停止”：已撤销的严格节点须等待原窗口结束；离线策略节点须先完成外部停止确认和严格策略迁移。其他拓扑发布、停用确认和逐节点应用规则保持原约定。

## 用量和配额

替换不会证明旧节点没有未上报用量。共享预算中的旧预留保持承诺，未知部分不退款、不转给新实例；控制器不会把观察不到的实际字节写成已确认消费。新实例只能从控制器已经确认的累计下限开始，原节点状态中尚未上报的字节仍需保留核对。

为防止全新状态复用旧规则额度，撤销会标记该节点**全部历史规则计量周期**。当前配置中仍启用、具有 `quota_bytes` 且使用这些周期的规则，会出现在 `blocked_quota_periods`，使新租约领取返回 423。预览和发布也拒绝重新启用这些旧配额周期，包括历史上已经换下的周期。

管理员可停用受影响规则，或在规则编辑器明确勾选“明确开始新计量周期”，再正常发布。新周期表示有意识地重新授予规则周期额度，旧账本仍保留；共享预算没有重置。删除配额表示显式撤销规则级限额，也不是恢复未知用量。不要把重新注册、换规则 ID 或换周期描述成对旧消费的补报。

## 恢复、升级和验收边界

当前身份、退役凭据和注册令牌标记、操作摘要、替换令牌有效期、撤销回执及旧计量周期保护均进入恢复日志。旧控制器备份加完整日志恢复后，它们保持一致；过期令牌不会续期，精确重放旧操作不会影响当前身份。任意旧快照回退、日志缺段或数据库与日志同时丢失仍没有新鲜度保证。

schema 保持 v4，但不表示可以安全降级。先升级控制器：新 Agent 的注册能力字段会被旧控制器拒绝；旧 Agent 不理解替换后的版本，不能用于替换注册。升级前备份当前控制器数据库、完整恢复日志和 head 清单，以及各节点私有状态。升级前已消费而未记录的历史注册令牌无法凭空补齐退役记录。

自动化测试覆盖权限、并发与幂等、事务失败回滚、旧窗口、旧状态拒绝、历史配额保护、注册响应丢失、离线模式停止确认以及恢复日志。独立 CLI 演练入口：

```sh
python3 scripts/check_replacement.py --binary target/release/relay --output docs/replacement-smoke.json
```

CLI 使用真实控制器和 Agent、临时隔离代理及 TCP/UDP，分别核对已知用量和未上报用量；规则配额保护由另行的 Rust HTTP/Agent 集成测试验证。具体证据见 [VALIDATION.md](VALIDATION.md)。页面只完成源码和语法检查；浏览器点击、Linux/WAN、多控制器、恶意主机强制隔离、未知预留权威回收和批量身份运维仍未验收或未实现。
