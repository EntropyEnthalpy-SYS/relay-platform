# 节点执行租约

0.13.0 增加由单一控制器协调的节点执行租约。同一节点在不同机器或不同状态目录启动时，严格模式只允许一个持有当前运行凭证的 Agent 进入对账、同步和业务执行。它约束本平台的协作式 Agent，不提供多控制器共识，也不是外部后端事务的隔离机制。

## 运行策略

HTTP 创建节点时，省略 lease_policy 默认采用 30 秒严格租约；传入 {"ttl_ms":5000} 等对象选择 5～120 秒窗口；显式传入 null 选择离线运行。管理界面采用相同默认值，并展示策略、当前保留状态和恢复等待。策略在节点创建后固定，当前没有在线切换或强制抢占接口。

- 严格模式：每次新进程先在线取得租约，再准备预算运行、对账和开启监听。0.14.0 只有原状态完整且所有权连续时才可验证并延续原预算运行；其他情况创建新运行，详见 [BUDGET_RECOVERY.md](BUDGET_RECOVERY.md)。等待取得租约的复制实例不会提前改动原预算运行编号或封存原预留。运行中独立续租；租约失效、被拒绝或续租监护异常结束都会停止接入并取消现有业务。控制器失联期间只能在剩余有效窗口内继续运行。
- 离线模式：保留已确认的本地配置与离线运行合同，不提供跨机器的同身份互斥。首次升级到新 Agent 时需要成功读取一次控制器策略，之后确认过离线策略的正常重启才可在控制器不可达时使用缓存。
- 已有节点不会被自动切换为严格模式。旧的 Rust Store.create_node 调用继续创建离线节点；HTTP API 与管理界面默认严格，新代码可显式调用 create_node_with_lease。

迁移策略需要创建新节点身份、停止并排空旧节点后再迁移配置。旧离线实例和复制品必须由操作者确认停止；控制器无法让没有连接控制面、也不遵守租约的新旧程序立即消失。0.16.0 已接入[常规凭据轮换](NODE_CREDENTIALS.md)，保留当前租约；紧急身份替换、撤销和在线策略迁移仍待实现。

## 身份和持久化

Agent 每次进程启动使用新的随机 256-bit 运行令牌。run_id 表示持久预算运行：通常新建，0.14.0 的原状态恢复验证成功后可跨进程沿用；令牌只存在于当前进程内存和控制请求中（跨机器强制 HTTPS，本机测试可用回环 HTTP），不写入 Agent 数据库或业务配置。控制器保存令牌 SHA256、运行编号、所有权代数和固定策略，放在既有 metadata 表的节点专属记录中，随控制器恢复日志一起提交。

新持有者增加代数。相同运行编号与令牌重复申请可以找回丢失的成功回复，但不会延长截止时间；续租必须同时匹配代数、运行编号和令牌。旧备份可能回退数字代数，随机令牌仍参与所有验证，不能仅凭数字相等认可旧持有者。

新的所有权和运行状态在同一事务内提交；新持有者出现时清除旧实例的配置回执、心跳和诊断，等待当前实例重新报告。领取租约本身不等于配置或业务健康。写入失败不会在内存中发布新的持有者，释放失败也不会提前允许接替。

每次同步和每一页对账都在存储事务内验证租约。严格节点的预算交换还要求 budget.run_id 与运行凭证一致；缺失证明返回 423，错误、过期或旧证明返回 409。校验在应用用量、额度及配置回执之前执行，批量同步仍隔离各请求的预期拒绝。

## 时间与恢复

控制器使用进程内单调时钟判断租约，不用可跳变的墙上时间直接决定接替。续租不改变持久化身份，只更新当前进程截止时间。冷启动后，所有已经存在的严格节点进入一个完整 TTL 的保守接替等待，即使旧备份中没有保存任何持有者。匹配持久化证明的原进程可以续租；另一个进程必须等到保留期结束。新创建的节点无需该等待。

Agent 的本地有效期从请求发出前计时，扣除网络/处理耗时，并额外扣除 TTL 的 10%（至少 250 ms）。通常每 TTL/3 发起续租；独立监护每 50 ms 检查截止时间，HTTP 正文卡住不延长它。单调时钟和墙上经过时间取较大值；墙上时间退到请求起点之前也按失效处理，迟到的成功回复不能复活已经失效的窗口。

这仍依赖客户端时钟速率和执行调度的合理边界。系统长期冻结、恶意更改时钟或绕过本程序的数据进程不由软件租约完全隔离；已交给内核的字节也不能撤回。租约只证明控制面的授权保留，不能声称外部后端具备 fencing token 校验。相关一致性前提可参考 [Redis 官方关于有效期、时钟漂移及 fencing 的说明](https://redis.io/docs/latest/develop/clients/patterns/distributed-locks/)。本平台使用自己的单控制器实现。

## 停止与额度

正常停止先关闭引擎和全部任务，再补报用量、归还已知未使用预留，并提交零活跃状态。只有这轮结算完成后才申请释放租约；报告或释放不确定时保留服务端截止时间，不把本地退出当作已经完成交接。结算与释放分别有两秒的网络清理期限。

Agent 任务被异常取消时，引擎释放逻辑也会取消监听、转发和探测。取消不是有序释放证明；控制器仍等待租约过期，之后新运行实例必须重新对账。进程突然终止、未上报消费和不完整恢复日志仍按原有账本/预算规则处理。

**租约到期不自动退款。** 它不证明旧实例未消费多少额度，也不解决双端状态同时丢失。0.14.0 可验证并延续原状态内保留的预留；它要求完整本地记录和连续所有权，不从租约过期推断余额。旧备份中的已封存预留可以接收控制器已确认的更高消费边界，但未知消费仍保守占额；双端状态丢失和任意快照回退的恢复仍待实现。

## API

创建节点：POST /api/v1/nodes，新增 lease_policy，沿用租户范围和写权限。GET /api/v1/nodes 增加 lease 对象：policy、generation、holder_run_id、active、remaining_ms、recovery_wait_ms；不返回运行令牌或哈希。active 指控制器仍保留该所有权，不代表转发进程实际存活。

Agent 使用原有节点 Bearer 凭据调用：

| 接口 | 请求 | 结果 |
| --- | --- | --- |
| POST /api/v1/agent/lease | run_id、token、generation=null | 申请或找回同一申请；其他有效持有者/恢复等待返回 423 |
| POST /api/v1/agent/lease | run_id、新 token、generation=null、resume_generation=原代数 | 仅连续原运行可申请恢复；发生接替返回 412，Agent 转为新 run_id 申请；仍有效的持有者/冷启动等待返回 423 |
| POST /api/v1/agent/lease | run_id、token、当前 generation | 续租；过期或身份不符返回 409 |
| POST /api/v1/agent/lease/release | proof、stats | 当前证明及零业务/探测状态才可释放；Agent 只在引擎停止和结算完成后调用 |

租约回复包含 required、generation、valid_for_ms、ttl_ms。离线策略返回 required=false、generation=null 和两个零时长。严格节点的同步与对账请求新增 lease={run_id,generation,token}；此证明从不作为管理页面字段。

resume_generation 缺省为 null，仅用于申请；不能与续租 generation 同时提供。恢复领取也增加代数，控制器保存 resumed_from；新随机令牌与新代数共同隔离前一进程，即使 run_id 没有变化。

数据库和日志仍为 schema v4。部署必须先升级控制器，再升级 Agent；新 Agent 不连接缺少租约接口的旧控制器。旧控制器不会解释新策略，不能对正在运行的严格节点直接降级控制器或 Agent；回退需要先停止相关节点并恢复配套版本和状态。

## 验证范围

测试覆盖并发领取、重试、过期、旧证明拒绝、预算运行绑定、事务失败、日志恢复、旧备份等待、真实 HTTP 权限、复制状态交接、持续续租、续租正文卡住、TCP/UDP 关闭、严格离线重启，以及 Agent 任务异常取消。当前完整结果以 [VALIDATION.md](VALIDATION.md) 的对应版本记录为准。

Linux 实机、真实时钟/休眠故障、跨主机长时网络分区、多控制器高可用、在线策略迁移和浏览器视觉/点击仍需各自验收。单台机器的多个进程不代表这些门槛已通过。

## 0.15.0 节点暂停与到期

严格节点可通过独立资料修订暂停运行或设置到期时间，完整合同见 [NODE_MANAGEMENT.md](NODE_MANAGEMENT.md)。暂停后领取/续租返回 403，到期后返回 410；已授有效证明仍可按原期限结算。截止期之前的 valid_for_ms 取 TTL 与距离到期的较小值，幂等找回也不延长窗口。Agent 继续扣除既有余量并独立停止，时间控制不依赖新的转发配置到达。

运行中不能把允许节点的到期时间改到已授窗口结束之前。暂停按当前窗口收敛，不能即时追回外部业务。节点 lifecycle 是运行许可，lease.active 是服务端保留，两者都不能替代实际业务健康。离线策略明确拒绝暂停/到期设置；完整策略迁移仍未完成。
