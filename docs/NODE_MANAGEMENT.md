# 节点资料与生命周期（0.15.0）

节点资料与转发配置分别保存。名称、类型、分组、标签、备注和成本的修改不会发布新转发修订，也不会主动重建已有连接；暂停和到期则接入严格节点的执行租约，实际限制业务运行。

## 资料字段

每个节点新增 profile={revision,updated_at_ms,settings} 和 lifecycle。旧数据库没有资料记录时读取为 revision=0、默认设置；首次保存生成第 1 版。新建节点直接生成第 1 版，之后每次成功保存递增；节点名称也受同一资料修订保护。

| settings 字段 | 口径与边界 |
| --- | --- |
| kinds | ingress、relay、egress、ix、nat 的不重复列表；可多选，默认未标注 |
| group | 可选分组名，最多 64 UTF-8 字节；null 表示未分组 |
| tags | 最多 32 个不重复标签，每个最多 64 UTF-8 字节；精确区分大小写 |
| notes | 最多 4096 UTF-8 字节，允许换行与制表符 |
| cost | 可选成本记录，见下文；null 表示未记录 |
| enabled | 默认 true；false 表示不再允许取得或续展执行租约 |
| expires_at_ms | 可选 Unix 毫秒时间戳，范围 1..253402300799999；null 表示未设置到期 |

名称长度为 1..120 UTF-8 字节。名称、分组、标签不接受首尾空白或控制字符。前端以每行一个标签编辑，类型复选框支持同一节点兼任多个用途。

类型是管理用途标注，不自动建立 NAT、IX 对接、反向隧道或路由。分组不改变租户归属或授权范围。成本、标签也不会在此版本自动参与路径选择，这些功能仍在完整清单中继续开发。

cost={currency,amount_micros,period}：currency 为三个大写字母的币种标记；amount_micros 为币种单位的百万分之一，允许 0..9000000000000000 的整数；period 为 monthly、yearly、one_time。前端用整数解析最多六位小数，避免二进制小数转换改变金额。它是成本记录，不执行支付、扣款、汇率换算或自动续费。

## 编辑、筛选与批量操作

POST /api/v1/nodes 可携带 settings；省略时使用默认资料。原 name、tenant_id 和 lease_policy 约定保持不变。

PUT /api/v1/nodes/{id}/profile 使用用户会话，提交：

```json
{
  "expected_revision": 1,
  "name": "台北入口",
  "settings": {
    "kinds": ["ingress", "relay"],
    "group": "亚洲组",
    "tags": ["premium", "台北"],
    "notes": "机柜 B",
    "cost": {"currency": "USD", "amount_micros": 12500123, "period": "monthly"},
    "enabled": true,
    "expires_at_ms": null
  }
}
```

settings 是整份设置；省略其中的子字段会恢复该字段默认值。前端基于当前完整资料编辑，不用局部 JSON 冒充完整更新。expected_revision 过期返回 409；客户端应重新读取并处理冲突。它与转发配置的 expected_revision 相互独立。

POST /api/v1/nodes/profiles 接收 {updates:[{node_id,update}]}，其中 update 是上述完整更新。一次允许 1..100 个不同节点，全部权限、修订、生命周期和存储检查通过才提交。任一失败回滚整批名称、资料和审计；成功返回每个节点的 {node_id,name,profile,lifecycle}。前端支持多选后设置/清空分组、增删标签、暂停或允许运行，并逐节点展示保存结果。

GET /api/v1/nodes 保留原列表响应，新增可组合的 q、kind、group、tag、lifecycle 查询参数。q 在名称、ID、备注、分组和标签中做不区分大小写的子串查找；分组和标签条件精确匹配。lifecycle=active/disabled/expired 表示运行许可，不能当作业务健康或在线状态。未知查询字段拒绝，筛选不会扩大租户权限。

租户管理员只能编辑本租户，系统管理员可跨租户，只读角色可以查看和筛选。外租户/不存在节点返回 404，只读角色写入返回 403。资料写入、名称变更及 before/after 审计在同一事务和恢复日志提交中完成。

## 暂停和到期的实际执行

这两项控制要求严格执行租约。离线策略允许缓存运行，无法保证远端及时停机；给离线节点配置 enabled=false 或非空到期时间会返回 400。策略本身仍在节点创建时固定，不能通过资料接口变更 TTL 或将离线节点静默转成严格节点。

- 暂停后，控制器拒绝新的领取和续租，返回 403。协作式 Agent 在续租被拒绝或本地有效期结束时关闭监听、现有 TCP、UDP、探测和聚合任务。已发出的有效窗口不会被网络请求即时追回，最长按当前租约窗口收敛；界面同时显示运行许可与仍保留的租约。
- 到期前，每次发放/续租的有效时长取 TTL 与距离到期时间的较小值；丢失回复的幂等领取不会延长已授窗口。到期后领取/续租返回 410。Agent 继续使用独立本地期限，即使控制器断联，也会在已收到的截止期前停止业务。
- Agent 会扣除 TTL 的 10%（至少 250 ms）作为现有安全余量，因此可能提前停止。到期过近、不足以建立保守有效窗口时，不启动监听。
- 当前有有效持有者时，将允许运行的节点改成早于已授窗口结束的到期时间会返回 409；从暂停恢复允许状态时也执行此检查，即使到期字段没有再次变化。应选择更晚时间，或先暂停、等租约释放/结束后再设定，不能将编辑保存等同于追回已经授出的时间。
- 暂停/到期不会清零用量或自动退还未知预留。仍在有效窗口内的原凭据可以补报、结算和释放；控制器不可达时保留未完成记录。恢复后按原状态额度恢复约定核对，见 [BUDGET_RECOVERY.md](BUDGET_RECOVERY.md)。

将 enabled 改回 true，或延长/清除到期时间，只恢复领取资格。已经退出的 Agent 需要重新启动；如果部署了重启服务，应由该服务的既定重启策略执行。重新启动仍遵守当前所有权、恢复等待和额度验证，不跳过旧预留保护。

控制器在同一进程内用单调经过时间和观察到的墙上时间推进到期判断，观察到的时间前跳不会因随后回拨而倒退。控制器重启后仍依赖正确系统时间；真实系统冻结、跨主机时间故障和恶意绕过程序不属于本轮已经验收的保证。租约的外部后端与时钟前提见 [NODE_LEASES.md](NODE_LEASES.md)。

## 恢复、升级与验证

节点资料存入既有 metadata 表并进入控制器连续恢复日志，schema v4 不变。旧备份加最新完整日志可以恢复名称、资料修订、成本、暂停和到期设置。仅恢复较旧快照不能证明后来的修改已经保留；实际恢复流程仍要求停止原控制器并使用完整日志。

先升级控制器与相关 Agent，再使用生命周期控制。旧控制器没有这项检查，不能将正在依赖暂停/到期的状态直接降级运行；schema 数字不变不是降级许可。Agent 会分别提示暂停/权限拒绝和到期原因。

自动化覆盖字段边界、成本精度、旧节点默认值、租户权限、过滤、并发编辑唯一胜出、批量冲突与存储失败回滚、日志恢复和时间前跳/回拨。真实 HTTP/Agent 测试验证资料修改保留同一 TCP 连接、暂停关闭 TCP/UDP、允许后重启，以及断联期间到期、过期重启拒绝、延长后补报和精确结算。

```sh
python3 scripts/check_node_profiles.py \
  --binary target/release/relay --output artifacts/node-profiles-smoke.json
```
