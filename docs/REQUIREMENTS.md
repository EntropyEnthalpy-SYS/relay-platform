# 全量验收清单

此清单保留完整范围，任何阶段性发布均不得将未实现项删去。状态以 `STATUS.md` 的验证证据为准。每个模块必须包含数据模型、权限、API、真实节点执行、适用界面与可重复验收；只有菜单不算完成。


下面是统一版的目标功能，不是三个产品已经实现完全相同细节的声明。每个模块都必须包含接口、持久化、节点执行、界面和验收；只存在页面入口不算交付。

| 模块 | 必须覆盖的功能 | 关键验收 |
| --- | --- | --- |
| 基础转发 | TCP、UDP、双协议、IPv4/IPv6、域名目标、端口段、绑定 IP/网卡、超时、DNS 缓存、PROXY protocol | 双向数据完整；地址族和目标切换符合配置；不支持的字段明确拒绝 |
| 安全传输 | TLS、WS、WSS、证书选择、自动续期、密钥轮换、双端参数校验 | 错误证书或参数必须失败；更新只影响明确范围 |
| 系统运维 | Linux 架构检测、systemd/OpenRC 适配、安装预检、服务自愈、日志轮转、离线包、卸载清理 | 清理仅作用于平台自有对象；恢复备份后可真实转发 |
| MPTCP | 能力检测、端点、子流、接口、路由、连接状态和普通 TCP 回退观测 | 能观察实际子流；不以开关开启代替聚合成功 |
| 节点管理 | 入口、中转、出口、IX/NAT 类型、标签、分组、备注、到期、成本、批量替换和升级 | 批量任务显示逐节点结果；离线节点恢复后收敛 |
| 配置编排 | 模板、版本、差异预览、引用检查、幂等下发、灰度、回滚、监听冲突预检 | 并发编辑不丢更新；失败配置不替换最后可用版本 |
| 拓扑与均衡 | 多跳链、候选组、多入口、加权轮询、源 IP 哈希、最少连接、健康权重、必经节点 | 正确区分候选组和顺序链；环路及不可达引用被发现 |
| 智能选择 | 端到端探测、分段探测、应用检测、多目标策略、成本与容量约束、防抖、回切 | 能解释当前选择和排除原因；故障注入时不产生路由振荡 |
| 多路径聚合 | 单连接跨路径、异速路径、汇聚端、路径权重、上下行选择、子流限额、复制模式 | 用单连接证明增益；重排内存有上限；复制额外流量可见 |
| 多协议 | 十二种入站选项的逐项可行性与兼容实现；出口代理；协议和安全层组合校验 | 协议、版本、TCP/UDP、认证、客户端分别有测试；未验收项不标支持 |
| 流量管理 | 端口、端口组、用户、租户、节点、共享资源计量；上下行及合并口径；额度、到期、周期重置 | 重启不丢已确认账；重传事件不重复扣量；跨周期归属稳定 |
| 带宽管理 | 单项及汇总限速、动态降速、突发、公平分配、节点硬上限、跨节点用户预算 | 多线程和多入口不能简单叠加突破约定上限；误差窗口有定义 |
| 用户权限 | 多用户、角色、资源范围、租户隔离、2FA、API scope、会话撤销、操作审计 | 普通账号无法引用其他租户资源；撤销权限即时按合同生效 |
| 运营交易 | 套餐、线路授权、价格周期、余额、订单、续费、补流量、优惠券、礼品码、支付、退款、佣金、公告、工单 | 回调重复不重复入账；退款可对账；套餐变更不静默损失权益 |
| 客户端订阅 | Clash、Surge、Shadowrocket、V2Ray/Base64 等格式，选择器、模板快照、预览、Token 轮换、限频 | 不兼容协议明确列出；旧链接失效与节点密码轮换分别验证 |
| NAT 与组网 | 反向隧道、TCP/UDP 服务暴露、WireGuard 网络、设备与成员、P2P、网关与中继回退、出口选择、路由排除 | UDP 单独测试；不能打洞时使用明确回退；管理链路不被路由覆盖 |
| DNS | 服务商 API、Webhook、DDNS、入口健康摘除、观察模式、最少保留数；可选独立权威 DNS 池 | 分清配置提交与外部 DNS 写入成功；识别共同故障和缓存延迟 |
| 分流与访问控制 | 域名、IP、CIDR、GeoIP、ASN、协议及组合规则；入站/出口 ACL；规则测试；流媒体出口策略 | 不可见的加密域名不强行推断；明确默认动作和规则优先级 |
| 资源共享 | 跨自有面板共享入口/端点、一次邀请、独立凭据、端口范围、带宽、到期、流量、暂停、撤销和双方对账 | 使用方不能扩大拥有方授权；撤销后节点实际拒绝旧凭据 |
| 监控诊断 | CPU、内存、连接、吞吐、丢包、抖动、分段耗时、历史查询、日志、探测、iperf3/路由诊断集成 | 控制在线与业务健康分开；图表标明缺失数据；诊断不越权 |
| 告警与自动化 | Telegram、邮件、通用 Webhook、企业微信/飞书/钉钉适配、告警合并、恢复通知、维护窗口、只读诊断 API | 相同事件合并；渠道故障可追踪；诊断角色不能执行写操作 |
| 备份与发布 | 配置和账本备份、密钥恢复、迁机、旧格式导入、版本固定、签名校验、组件清单、升级回滚 | 在干净环境恢复并验收真实业务；源码能重建发布物 |

Hammer 的名称、专有协议格式和 Zero 的共享码格式不属于已经取得的可复用实现。Snell 等协议也要分别确认实现来源、许可和客户端版本。功能等价与协议互通应设为两条验收线：先完成自己的公开隧道与聚合能力；要连接原产品或指定客户端时，再依据可用规范和测试向量实现并验证兼容。缺少资料的兼容项保留为未解决项，不能声称已覆盖。


## 发布门槛

除模块验收外，完整发布还需要：两台真实 Linux 节点；干净环境源码重建；故障注入；备份与迁机演练；跨租户权限测试；并发及吞吐报告；72 小时混合负载稳定性验证。性能结果必须记录软硬件条件。
