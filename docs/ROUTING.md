# 端口段、出口绑定与目标 DNS

0.6.0 的配置、控制 API、Agent、standalone 和规则编辑表单共用以下字段。新增字段均可省略；未识别字段仍拒绝。没有启用缓存时，域名目标继续使用操作系统解析。

```json
{
  "listen": "127.0.0.1:19100",
  "listen_end_port": 19101,
  "port_mapping": "offset",
  "outbound_bind": {"ip": "127.0.0.1", "interface": null},
  "dns_cache": {
    "servers": [],
    "capacity": 1024,
    "max_ttl_secs": 300,
    "negative_max_ttl_secs": 5
  },
  "targets": [{"address": "127.0.0.1:19200", "weight": 1}]
}
```

上面是规则片段；可校验的完整例子在 [port-range.json](../examples/port-range.json)。

## 端口段

`listen_end_port` 包含结束端口；省略或 null 表示单端口。每条规则最多 256 个连续端口，每个节点最多 4096 个 TCP/UDP 监听套接字，双协议占两个。所有端口使用同一监听 IP、协议、目标组、来源 ACL、TLS 设置、计量周期和规则身份。

`port_mapping` 默认 `fixed`：每个入口使用相同目标端口。`offset` 按 `入口端口 - 首个监听端口` 加到每个目标端口；例子将 19100/19101 分别连到 19200/19201。目标端口溢出、监听范围倒序、重叠或超过上限均拒绝。

所有端口共享合并额度、令牌桶、TCP 连接上限和 UDP 会话上限，不能通过扩大端口段获得额外额度。现有计量表按规则/周期记录，未增加每端口明细账。端口段中的不同 UDP 入口仍各自维护来源会话；总会话数跨端口共享。

所有新监听准备成功后才提交配置。任一端口冲突会释放本次准备的监听并保留旧版本。修改目标只作用于新会话；已有 TCP 连接继续使用旧目标。删除端口会停止该监听的 UDP 会话；已接受的 TCP 连接遵循原有连接生命周期。删除整条规则会取消所有旧连接。

## 出口 IP 和网卡

`outbound_bind.ip` 是具体的源 IP，`interface` 是 Agent 操作系统中的网卡名称；可单独或同时设置。两项均空无意义，拒绝配置。指定 IP 必须与字面量目标地址族一致；域名同时解析出两种地址族时，逐个尝试与绑定相容的地址。IPv4-mapped IPv6 目标先规范化为 IPv4。

Linux/Android 使用 `SO_BINDTODEVICE`，macOS 使用 `IP_BOUND_IF`/`IPV6_BOUND_IF`。其他操作系统当前明确拒绝网卡绑定。IP 和网卡同时设置时，IP 必须属于该网卡。预检会实际创建和绑定业务套接字；网卡不存在、IP 不在本机或权限不够都会拒绝应用。拨号时也执行绑定，失败不会降级成系统自动选路。Linux 网卡权限和真实路由尚未实机验收；macOS 回环已覆盖 TCP、UDP 和两个地址族。

绑定约束业务 TCP/UDP 套接字，不约束控制面 HTTPS 或 DNS 查询；后两者仍走系统路由。预检只能确认配置当时可绑定，不能保证远端可达。网卡、IP 或路由之后变化仍可能使连接失败。

所有 IPv6 监听明确使用 `IPV6_V6ONLY`；`[::]:端口` 不接收 IPv4。需要双栈时同时配置 IPv4 和 IPv6 监听，可使用相同端口。此行为相对之前依赖操作系统默认值的版本有所收紧，升级时应检查原先只有 IPv6 通配监听的配置。

## 目标 DNS 缓存

`dns_cache` 省略/null：使用 Tokio 的操作系统解析入口，本平台不增加应用缓存。存在该对象时，使用锁定版本的 Hickory Resolver；空对象使用上述默认值。

- `servers` 最多 4 个具体 IP:端口，IPv6 用方括号；为空时读取系统 DNS 配置。显式服务器配置支持普通 UDP/TCP DNS，不提供 DoH/DoT 开关。
- `capacity` 为缓存响应数量配置，范围 1..4096；不是单个 IP 数。每次拨号最多取 64 个解析地址，相同 DNS 配置的规则共享 resolver，每个节点最多 16 种启用的配置。
- 正响应不超过自身 TTL 与 `max_ttl_secs`（0..3600）的较小值；没有人为延长短 TTL。0 禁用正响应复用。
- 不存在记录/无所需类型的负响应按 DNS SOA 信息与 `negative_max_ttl_secs`（0..60）限制；不会把任意网络错误固定缓存为不存在。
- 查询 A 与 AAAA，先尝试 IPv4；IP 字面量跳过 DNS。保留系统 hosts 文件查找。启用缓存不会完整模拟所有平台专有名称服务；例如 Bonjour、企业分域解析应另行验收。
- 解析、逐地址拨号及出口 TLS 共用连接超时截止时间；失败可以尝试下个目标，但不重新获得完整超时。UDP `connect` 不代表对端业务健康。
- 缓存过期影响新连接/新 UDP 会话；已有连接不因 TTL 到期迁移。DNS 配置或出口绑定变更会取消该规则已有会话；普通目标变更保留已有会话。相同 DNS 配置在新修订中复用缓存。

这是业务目标解析缓存；DNS 服务商 API、DDNS、权威 DNS 与健康摘除仍属于未完成的第 17 模块。

## 节点内环路保护

发布校验检查 IP 字面量目标与配置中的监听，拒绝直接、多跳及端口偏移造成的环路。Agent 应用时加入实际网卡地址；通配监听只匹配本机地址，不会因远端恰好使用相同端口而误判。

每次拨号前检查解析所得地址。连接到本 Engine 其他监听时登记一条活跃有向边，TCP/UDP 会话结束释放。新增边若沿配置边或活跃边返回来源监听则拒绝，避免域名改为本机或两条域名规则互指。旧配置仍存活的连接继续保留边，必要时保守拒绝新方向，直到旧连接结束。无环的本机转发链可用。

保护范围是同一个 Engine 管理的监听。其他进程/Agent、跨节点转发、网络 NAT 重定向、外部 UDP 端口被替换成平台监听等需要完整拓扑与网络观测；当前不保证检测这些环路。错误计入已有 TCP 失败/UDP 丢弃统计；debug 日志记录会话失败，TCP 保留最后一次目标错误，UDP 目前只给出解析/连接失败摘要，尚无独立环路告警计数。不能将此功能宣称为完整多跳拓扑模块。

## 升级与验收

SQLite schema 仍为 v4，恢复日志格式不变。旧配置不含新字段时可读取；0.5 Agent 会严格拒绝新字段，先升级节点再发布新能力。管理页面已提供字段，浏览器视觉与点击验收仍未完成。

`tests/network_features.rs` 使用本机真实 TCP/UDP 和可改变回答的 DNS 服务器，检查共享额度/连接限制、偏移映射、失败回滚、绑定、TTL/负缓存/零 TTL、解析地址族、旧连接环路和 IPv6 监听语义。最终数量与结果见 [VALIDATION.md](VALIDATION.md)。

实现依据：[Socket2 套接字接口](https://docs.rs/socket2/0.6.5/socket2/struct.Socket.html)、[Hickory TTL 配置](https://docs.rs/hickory-resolver/0.26.3/hickory_resolver/config/struct.ResolverOpts.html)、[if-addrs 接口枚举](https://docs.rs/crate/if-addrs/0.15.0)。具体构建版本由 Cargo.lock 固定。
