# Shadowsocks 代理服务

0.19.0 起，规则可以作为 Shadowsocks 服务器：客户端（Shadowrocket、Clash、sing-box、v2rayN、shadowsocks-rust 等）在每个连接里指定要访问的地址，节点解密后直接连接该地址。协议依据公开规范 [SIP022（2022 版）](https://github.com/Shadowsocks-NET/shadowsocks-specs/blob/main/2022-1-shadowsocks-2022-edition.md) 与 [SIP004（AEAD）](https://shadowsocks.org/doc/aead.html) 自行实现，没有引入商业产品或 shadowsocks-rust 的代码；shadowsocks-rust 只作为外部互通测试客户端。

TCP 与 UDP 都已支持（规则协议选 `tcp`、`udp` 或 `both`，建议 `both`，客户端的 QUIC、DNS、游戏和语音才能经过本节点）。多用户（同一端口多把密钥）和插件（如 v2ray-plugin、shadow-tls）尚未实现。

## 配置

```json
{
  "id": "tokyo-ss", "name": "东京 Shadowsocks", "listen": "0.0.0.0:8388", "protocol": "both",
  "inbound_shadowsocks": {"method": "2022-blake3-aes-256-gcm", "password": "<openssl rand -base64 32>"},
  "targets": [], "meter_epoch": "2026-10", "tenant_id": "default", "owner_id": "admin",
  "quota_bytes": null, "expires_at_ms": null, "rate_bytes_per_sec": null
}
```

| 字段 | 含义 |
| --- | --- |
| `method` | `2022-blake3-aes-128-gcm`、`2022-blake3-aes-256-gcm`、`2022-blake3-chacha20-poly1305`，或旧版 `aes-128-gcm`、`aes-256-gcm`、`chacha20-ietf-poly1305` |
| `password` | 2022 方式：该方式长度（16 或 32 字节）的 base64 密钥；旧版方式：1..256 字节的密码，按所有客户端相同的 EVP_BytesToKey 转为密钥 |
| `allow_private_destinations` | 默认 `false`：拒绝回环、私有网段（10/8、172.16/12、192.168/16、100.64/10）、链路本地（含 169.254.169.254 云元数据）、ULA、组播、保留与文档地址，以及可映射到 IPv4 私网的 NAT64 / IPv4 兼容 IPv6；域名解析后逐个检查。设为 `true` 时客户端可访问节点所在内网 |

- `targets` 必须为空；不能同时启用入口 TLS、入口 WebSocket、多路聚合或健康检查。可与入口 PROXY 报头、来源 ACL、配额、限速、到期、出口绑定和 DNS 缓存同时使用；出口绑定和 DNS 缓存作用于客户端请求的目的地址。
- 控制台“添加规则”中展开“Shadowsocks 代理服务”，选择加密方式后自动生成密钥；规则列表的“分享链接”生成 SIP002 `ss://` 链接（2022 方式不做 base64，旧版方式为 URL 安全 base64），可直接导入客户端。客户端经入口节点中转时，链接中填写入口节点的地址和端口。
- 改动方式、密钥或内网策略会终止该规则的现有连接，旧密钥立即失效。0.20.0 起，只改名称、限速、健康策略等不改变加密身份的替换会沿用同一 TCP 盐缓存，已捕获请求在时间戳窗口内仍被拒绝；改密钥或方式则使用新的重放域。日志与调试输出不包含密钥；能读取规则配置的控制台用户可以看到密钥。

## 行为

- 2022 方式：请求头时间戳与节点时钟相差超过 30 秒即拒绝；60 秒内重复的盐被视为重放；请求必须带初始数据或非空填充（最多 900 字节）。单块最多 65535 字节。
- 旧版方式：单块最多 16383 字节；60 秒内重复的盐被拒绝，但旧版协议本身没有时间戳，更早请求的重放无法识别，建议优先使用 2022 方式。
- 任何错误的请求（密钥不对、伪造、超时、时间戳过期、重放、地址非法）都不回复：节点先发送 FIN，再读取并丢弃对方数据直到对方关闭或 60 秒，使探测者无法从关闭时机判断节点读了多少字节（SIP022 §3.1.3 策略 2）。这些连接计入节点 `rejected_connections`。
- 计量、配额和限速按客户端与目的地之间的应用数据计算，Shadowsocks 盐、长度块、数据报头和认证标签不计费。

## UDP

- 每个客户端会话（2022 方式按客户端会话 ID，旧版方式按客户端地址）对应一个关联：节点为它各开一个 IPv4 / IPv6 出口套接字，客户端每个数据报指定的目的地都从这里发出，任何地址发回这些套接字的数据都加密后回给客户端，并标明来源地址（与官方服务端相同的完全锥形行为）。默认策略下，非公网目的地和非公网来源的回复都被丢弃。
- 2022 方式：数据报时间戳与节点时钟相差超过 30 秒即丢弃；每个关联用滑动窗口记住最近 2048 个包号，重复或过旧的包号丢弃，窗口只在数据报通过认证和时间检查后才前移。关联按会话 ID 查找，客户端换了 IP 或端口（如手机切换网络）后，回复发往最新的来源地址。关联在最后一个数据报后至少保留 60 秒（规则空闲回收时间更长时按规则）；因规则修改、配额用尽等提前结束时，它的包号记录仍保留 60 秒。所以被截获的数据报在时间戳过期前无法借新关联重放。
- 旧版方式：每个数据报自带盐，协议本身没有时间戳和包号，重放无法识别（官方服务端同样不检查），建议优先使用 2022 方式。
- 目的地为域名时，每个关联每 60 秒最多解析一次，并优先使用 IPv4 地址：UDP 发往不可达的 IPv6 地址不会报错，无法像 TCP 那样换下一个地址重试。
- 关联数受规则“UDP 最大会话”限制；错误密钥、伪造、过期、重放或地址非法的数据报一律静默丢弃，不回复，计入节点 `dropped_datagrams`。入口 PROXY v2 对每个数据报生效，来源 ACL 按报头中的客户端地址执行。

## 中转用法

最常见的两跳：用户 → 入口节点（普通转发规则，协议与出口相同，目标为出口节点的 Shadowsocks 端口）→ 出口节点（Shadowsocks 规则）→ 网站。入口只转发密文，不需要密钥；链接中的地址填写入口节点。出口节点的 Shadowsocks 端口可用来源 ACL 只允许入口节点访问。

## 验证

`scripts/check_shadowsocks_interop.py --sslocal <shadowsocks-rust sslocal> --output <json>` 用 shadowsocks-rust 客户端依次测试六种方式：TCP 的 IP 与域名目的地、半关闭、4 MiB 双向逐字节校验，UDP（SOCKS5 UDP ASSOCIATE）0～60000 字节的数据报、IP 与域名目的地和回复来源地址；以及默认策略拒绝回环、错误密钥和重放（TCP 与 UDP），2022 关联跟随客户端换地址、乱序包号只接受一次、规则修改结束关联后重放仍被拒绝，并核对账本只记录应用数据。结果见 [VALIDATION.md](VALIDATION.md)。
