# 共同规则：一条规则同时运行在多台入口服务器上

共同规则（英文界面 Shared rule）把同一条转发规则放在多台入口服务器（“线路”）上，所有线路使用同一个监听端口。名称、目标、协议、限速等设置只填写一次；创建、修改、暂停和删除都一次作用于全部线路，并带逐线路预检。它对应 Zero Forwarder 的“多线路共同维护”。

共同规则只负责“多个入口提供同一个服务”。各入口仍是独立的连接地址：客户端连哪个入口，由客户端配置、订阅或另行配置的 DNS 决定。它不做入口故障切换，也不聚合单个连接的带宽；入口按健康摘除见 [DNS 健康摘除](DNS.md)，单连接带宽聚合见[多路径](MULTIPATH.md)。

## 数据与安全边界

- 每条线路上的成员都是那台服务器上的**普通规则**，经同一套配置发布路径校验和下发。Agent 协议、发给 Agent 的规则格式都没有变化，旧版 Agent 照常运行。
- 控制器只另存一条成员记录：`metadata` 中的 `shared_rule:<id>`，内容为 `id`、`tenant_id`、`name`、`listen_port`、`members:[{node_id, rule_id}]`、`created_at_ms`、`updated_at_ms`。schema、恢复日志格式、备份和连续恢复都不变。
- 每次修改都在**一个事务**里写入成员记录并以一个配置批次发布所有涉及的服务器：每台服务器的期望修订在事务内重新读取，逐台检查写权限、修订号和配置校验，任何一台失败则全部不变。每条共同规则最多 32 条线路，因此即使一次修改换掉全部线路，新旧线路之和也不超过配置批次的 64 台上限。
- 权限与规则相同：读取需要登录会话或带 `read` 的 API 令牌；预检和所有修改需要可写角色，API 令牌还需 `nodes:write`。只读用户（viewer）修改时返回 403。共同规则属于其线路所在的租户：所有线路必须属于同一租户；其他租户看不到它，访问返回 404。
- 审计动作为 `shared_rule.create`（新建和“扩展到多条线路”）、`shared_rule.update`、`shared_rule.pause`（暂停和恢复，详情含 `paused`）、`shared_rule.delete`（详情含 `keep_rules`）。发布本身仍记录 `config.publish`，涉及多台时另有一条 `config.batch_publish`。
- 一条规则最多属于一条共同规则。

## 共同字段与每条线路自己的字段

除下列“线路身份”外，规则的所有字段都是共同字段，包括名称、监听端口、协议、目标与均衡、健康检查、入口 TLS / WebSocket / PROXY、代理服务凭据、配额、限速、到期时间、来源与目的地 ACL、是否启用等：

| 字段 | 每条线路如何确定 |
| --- | --- |
| `id`、`meter_epoch` | 新线路得到新的规则编号和计量周期；已有线路保留，只有监听端口改变时才换新的计量周期 |
| `owner_id` | 已有线路保留；新线路沿用第一条线路的所有者（新建时为请求中的 `owner_id`，省略则为操作者） |
| `tenant_id` | 线路所在服务器的租户 |
| 监听地址的 IP | 新线路取服务器资料“转发设置”的监听 IP；未设置监听 IP 时与自动分配端点相同（按转发主机推断：IPv6 主机为 `::`，回环主机为回环地址，其余为 `0.0.0.0`）；没有转发设置时为 `0.0.0.0`。已有线路保留自己的监听 IP |
| `advertise` | 上一跳连接本规则用的地址，必然因服务器而异，按线路保留；新线路为空 |
| `budget_ids` | 由控制器按节点 / 租户 / 用户计算，不比较 |

共同规则只监听一个端口：不支持端口段（`listen_end_port`），也不支持受管协议网关（它在每台服务器上还需要一个私有桥接端口）。跨面板共享产生的 `fed-` 规则不能成为共同规则。

限速和配额按每条线路各自执行：例如限速 100 Mbit/s，表示每台服务器上的这条规则各 100 Mbit/s，不是所有入口共用一份。

## 端口与预检

一台服务器的**端口范围**取服务器资料“转发设置”的 `port_start`–`port_end`，没有转发设置时为 20000–29999（与自动分配端点相同）。

`POST /shared-rules/precheck` 逐线路返回：

| 字段 | 含义 |
| --- | --- |
| `online` | 90 秒内有心跳 |
| `in_range` | 端口在该服务器的端口范围内。仅作提示：范围外的端口（例如所有入口统一用 443）也可以保存 |
| `port_free` | 该服务器上没有其他规则监听这个端口，也没有端口段包含它；停用的规则、任何监听 IP、受管协议网关的公开端口，以及未撤销的跨面板共享端口段都算占用。编辑时（请求带 `id`）该共同规则自己的成员不算 |
| `valid` / `error` | 用这台服务器的候选配置执行与发布相同的校验（`preview_configs`）的结果 |

`listen_port` 为 `null` 时自动选号：在所选服务器端口范围的**交集**中，选在所有线路上都空闲的最小端口并返回；交集为空或没有空闲端口时返回 `listen_port:null` 和 `error`。整体批次的校验错误（例如跨服务器的路径校验）放在顶层 `error`。`ok` 表示每条线路端口空闲且校验通过。

预检**不预占端口**：保存时会在同一把锁下重新检查，期间别的修改占用了该端口，保存仍会返回 409。

## 操作

- **新建**：为每条线路新建一条规则（新编号、新计量周期），一个批次发布；任一线路端口被占用返回 409 且不修改任何服务器。
- **从已有规则扩展**：原规则成为第一条线路，保留编号、端口和流量统计，原服务器不重新发布；在新增服务器上以同一端口新建相同配置的规则。原规则已属于某条共同规则时返回 409。
- **编辑**：把共同字段统一到每条线路；增加的线路按上表新建（并检查端口）；移除的线路删除该服务器上的成员规则；没有变化的服务器不重新发布。修改统一监听端口时，所有成员一起换号，各线路换新的计量周期，流量统计从零开始。不能移除全部线路（400），要全部删除请使用删除。规则或服务器已不存在的成员在保存时静默移出记录。
- **暂停 / 恢复**：把每条线路的 `enabled` 设为 false / true，一个批次发布；已是目标状态的线路不重新发布。
- **删除**：一个批次删除全部线路上的成员规则，再删除记录；`?keep_rules=true` 只删除记录，各线路上的规则保留为普通规则。
- **单独修改成员**：在“按服务器”中单独编辑或删除某条线路的规则仍然允许。编辑后它与第一条线路的差异显示为“线路配置不一致”（`drift`），删除后该线路显示为已缺失（`missing`）；下一次保存共同规则会把差异统一为表单的值。删除一台服务器不受共同规则阻止，该线路随之显示为已缺失。

监听地址或路由属于多跳拓扑的规则（有 `advertise` 或下一跳引用）仍受[拓扑](TOPOLOGY.md)的停用规则约束：运行中不能改动其路由，需要先暂停并等待服务器确认。

## 入口地址

列表为每条线路给出可复制的入口地址：服务器设置了转发主机时为“转发主机:端口”（有公网端口映射且端口在范围内时换算为公网端口）；否则为该规则的 `advertise`；再否则在监听具体 IP 时为监听地址；都没有时为 `null`，面板提示“未设置转发地址”。

## API

| 方法 | 路径 | 请求 / 结果 |
| --- | --- | --- |
| GET | `/api/v1/shared-rules` | 可见的共同规则：`[{id, tenant_id, name, listen_port, created_at_ms, updated_at_ms, drift:[path], members:[{node_id, rule_id, node_name, missing, rule, entry, drift:[path]}]}]` |
| POST | `/api/v1/shared-rules/precheck` | `{node_ids, listen_port\|null, rule, id?}` → `{listen_port, ok, error, lines:[{node_id, node_name, online, in_range, port_start, port_end, port_free, valid, error}]}`；不写任何数据 |
| POST | `/api/v1/shared-rules` | `{name, node_ids, listen_port, rule}`；1–32 台、不重复、同一租户 |
| POST | `/api/v1/shared-rules/from-rule` | `{node_id, rule_id, add_node_ids}` |
| PUT | `/api/v1/shared-rules/{id}` | `{name, node_ids, listen_port, rule}`：完整的线路列表和共同字段 |
| POST | `/api/v1/shared-rules/{id}/pause` | `{paused: true\|false}` |
| DELETE | `/api/v1/shared-rules/{id}[?keep_rules=true]` | `{ok:true}` |

`rule` 是普通规则对象，只取共同字段：`id`、`tenant_id`、`meter_epoch`、`name`、`listen` 可以省略（名称以外层 `name` 为准，端口以 `listen_port` 为准），`owner_id` 省略时为操作者；未知字段返回 400。修改类接口返回与列表项相同的对象。

`drift` 的路径以第一条现存线路为基准，例如 `targets[0].address`、`rate_bytes_per_sec`、`listen_port`；数组长度不同时报告数组本身（如 `targets`）。

错误：输入无效 400，权限 403，不存在或不可见 404，冲突 409（某线路端口被占用、修订已变化、规则已属于共同规则）。能确定原因所在线路时，错误体带 `lines`：

```json
{"error": "port 26000 is already used on 1 of the selected servers",
 "lines": [{"node_id": "…", "error": "port 26000 is already used on this server"}]}
```

批次校验失败时，控制器再逐台校验，把出错的服务器列在 `lines` 中。

## 面板

「转发规则」的“全部转发”和“按服务器”两个页面下方都有“共同规则”区块：名称与“共同规则 · N 条线路”、每条线路的端口和状态（已暂停、已缺失、节点应用状态、与第一条线路不同）、入口地址与“复制全部”、目标，以及“编辑”“暂停 / 恢复运行”“删除”。删除对话框列出将删除的线路和端口，可选择只删除共同规则、保留各线路上的规则。

“＋ 新建共同规则”打开与普通规则相同的规则编辑器：先填名称、勾选线路、填写统一监听端口，“自动选号”和“检查”在下方显示逐线路预检表；目标、协议、限额等设置与普通规则相同。“按服务器”的规则操作中，普通规则有“扩展到多条线路…”，成员规则有“编辑共同规则”，规则名称下显示“共同规则 · N 条线路”。

## 验证与限制

- `crates/relay-platform/tests/shared_rules.rs` 12 项集成测试：一个批次在每台服务器发布相同规则（含按转发设置的监听 IP）；端口被某台服务器的端口段占用时整体失败且不修改任何服务器；不对称端口范围下自动选号得到交集内全部空闲的最小端口、手动端口的占用与范围提示；编辑保留编号和计量周期、换端口时更换计量周期并保留各线路监听 IP；增删线路且未变化的服务器不重新发布、不能移除全部线路、已缺失成员在保存时移除；暂停 / 恢复；删除与 `keep_rules`；单独编辑后的 `drift` 与再次保存后清除；从已有规则扩展保留原编号、重复扩展 409、端口段规则 400；租户隔离与只读用户 403、跨租户线路 400；删除服务器后线路显示为已缺失；HTTP 接口的逐线路 409、预检、只读用户 403、API 令牌只有 `read` 时可读不可预检而 `nodes:write` 可以、暂停、移除全部 400、`keep_rules` 删除与从规则扩展冲突。另有 2 项单元测试覆盖 `drift` 计算和请求中规则的读取。
- `scripts/test_web_shared_rules.cjs` 在中英文下运行面板代码，核对新建（自动选号、检查）、编辑、扩展、暂停 / 恢复、删除（含保留规则）和“复制全部”发送的请求。
- 预检的 `online` 只是提示：离线服务器也可以加入，它重新连接后按期望配置应用。保存成功只表示期望配置已提交；各服务器是否已应用、防火墙是否放行、入口是否可达，仍需在“节点应用状态”和客户端逐个确认。
- 不支持服务器组（成员随组增减）、端口段、受管协议网关和多选批量编辑中的“增加 / 移除线路”。没有端口额度（按线路计数的配额）概念。
