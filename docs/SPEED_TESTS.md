# 测速：服务器测速与路径测速

Relay 内置两类测速，对应 Zero Forwarder 文档中的“速度诊断”和“全球测速”：

- **服务器测速**（仅系统管理员）：一台服务器到 Cloudflare 公共测速服务的上传 / 下载速度，或两台服务器之间的速度。
- **路径测速**：按一条转发规则实际经过的服务器逐段测速（入口 → 下一跳 → … → 末跳），并测末跳到业务目标的 TCP 连接耗时。

测速是 Agent 内置的固定代码，参数有上下限。Agent 不会执行面板下发的程序或脚本，也不会访问面板指定的任意网址：公共测速服务固定为 `https://speed.cloudflare.com`，服务器之间只连接控制器按服务器转发设置算出的地址。

## 方式

### 服务器 ↔ Cloudflare

测速服务器用 HTTPS 访问 Cloudflare 的固定地址：

- 下载：`GET https://speed.cloudflare.com/__down?bytes=N`，每个请求最多 25 MB，在时长内循环请求；
- 上传：`POST https://speed.cloudflare.com/__up`，请求体从 256 KiB 开始，完成得快就加倍（最多 8 MiB），慢于 2 秒就减半，慢速线路也能每一两秒得到一个数据点。

Cloudflare 会限制同一地址短时间内下载的数据量：超过后回答 HTTP 429（单个下载请求达到 100 MB 时回答 403，所以每个请求最多 25 MB）。快速服务器在测试中途就可能被限制。已经测到数据之后收到 429，该流就此结束而不算失败，结果标记 `limited: true`，只包含被限制之前的部分，面板会注明；一开始就收到 429 时测速失败，错误为 `speed.cloudflare.com is limiting tests from this server (HTTP 429); try again in a few minutes`，通常几分钟后恢复。

不使用系统代理，不跟随重定向，连接超时 10 秒。测速服务地址不能通过 API、配置或命令行参数修改；只有集成测试用一个测试专用入口（`agent::run_with_speed_test_service`，`#[doc(hidden)]`）把它指向本地模拟服务。

### 服务器 ↔ 服务器

- **测速服务器**（发起连接）连接**对端服务器**（临时监听、接收连接）。
- **上行**是测速服务器发往对端，**下行**是对端发往测速服务器。由接收数据的一端计量：上行由监听端计数，结束时把每 100 毫秒的计数发回给测速服务器，由它回报；下行由测速服务器计数。
- 对端在**转发监听 IP**（未设置时为 `0.0.0.0`）上监听测试端口：管理员可指定端口（1024–65535），留空时控制器从对端**转发端口范围**中从高到低选第一个没有被规则（含端口段、协议网关端口）、反向隧道（公网端口与隧道端口）、共享规则的线路或跨面板共享占用的端口。指定的端口被占用时为 409。
- 测速服务器连接对端的**转发地址**，端口按对端的公网端口映射（NAT 端口范围）换算，与反向隧道相同。两台服务器任何一台没有转发地址时拒绝（409），并说明原因。
- 每次测速、每一段生成一个 32 字节随机令牌。每条测试连接的前 42 字节为 `RLYSPD01` + 令牌 + 方向字节（`U`/`D`）+ 流序号；监听端用常数时间比较令牌，5 秒内没有发完、令牌不符、方向或流序号不在本次参数内、或同一个流重复连接的，一律直接关闭，并计入“拒绝的连接”。监听端同时最多处理 32 个连接。
- 发起端在 15 秒内重试连接，以等待对端打开监听；两端都从该方向第一个流连通时开始计时，等待的时间不计入测速时长。全部预期的流结束后监听端口立即关闭；取消时两端都停止；即使收不到控制器的消息，任务也会在硬超时（每个方向 `2 + 时长 + 20` 秒，再加 15 秒）后自行结束。

### 路径测速

对一条规则（单跳、经 `via` 的多跳，或由保存的链路、共享规则生成的规则），控制器从入口规则出发，沿每一跳**首选目标**（优先级最高、未暂停的第一个目标）的 `via` 找到下一跳，最多 16 跳，检测环路：

- 每一段是“本跳服务器 → 下一跳服务器”的服务器 ↔ 服务器测速。发起端连接的主机与本跳规则目标使用的主机相同（因此走的是两台服务器之间的真实线路），端口为下一跳服务器上临时选出的测试端口（按其公网端口映射换算）。
- 各段依次进行，每段都完成所选的方向。
- 末跳的目标是固定 TCP 目标时，再从末跳测一次到业务目标的 **TCP 连接耗时**（只建立连接，不发送数据；解析出的地址最多试 4 个，每个 5 秒超时）。末跳是代理服务（没有固定目标）或只有 UDP 时不测这一项。
- 结果标出**最慢的一段**：按每段较慢方向的平均速度比较。
- 同时列出路径上每条规则和每台服务器配置的限速（合计、上传 / 下载与突发）和规则配额，并明确说明**本测试不经过规则，这些限速不生效，测速流量也不计入规则的配额或共享额度**。

不能做路径测速的规则（409，界面显示原因）：

- 代理服务（Shadowsocks、SOCKS5、HTTP CONNECT 等）和受管协议网关：没有固定目标；
- 反向隧道的公网端（`rt-…`）：它经隧道到达目标，请改用两台服务器之间的服务器测速；
- 来自其他面板的跨面板共享规则（`fed-…`）；
- 只在一台服务器上、又没有 TCP 目标可测连接耗时的规则；
- 下一跳已不存在、路径过长或形成环路的规则。

## 参数

| 参数 | 范围 | 默认 |
| --- | --- | --- |
| 方向 `direction` | `upload`、`download`、`both`（先上行后下行） | 必填 |
| 时长 `duration_secs` | 每个方向 5–60 秒（不含预热） | 10 秒 |
| 数据量 `bytes` | 每个方向 1,000,000–1,000,000,000 字节，各流平分；仍最多运行 60 秒 | 不用 |
| 并行 TCP 流 `streams` | 1–8 | 4 |

时长和数据量只能选一项；都不给时按 10 秒。超出范围为 400。Agent 收到任务时会再次校验。

## 结果的计算

接收端把收到的字节按距该方向开始的时间放入 100 毫秒的桶中：

- **预热**：前 2 秒（20 个桶）不计入结果，排除 TCP 慢启动和建连时间。
- **测量窗口**：从预热结束到最后一个有数据的桶，最长到“预热 + 时长”。按数据量测速时，如果预热之后不足 1 秒就传完了，则整段传输都计入。
- **平均**：窗口内字节 × 8 ÷ 窗口时长，单位 bit/s。
- **峰值（1 秒）**：窗口内任意连续 10 个桶（1 秒）的最大比特数；窗口不足 1 秒时峰值等于平均。
- 每个方向报告：平均、峰值、测量字节数和测量时长、并行流数、失败的流数和最多 4 条错误（每条最多 200 字符）。监听端拒绝的连接数显示在该段上。

计算在 `crates/relay-platform/src/speed_test.rs` 的 `summarize`，单元测试用合成数据验证预热排除、平均和 1 秒峰值。

## 不测什么

- 测速流量使用 Agent 自己新开的套接字，**不经过任何规则**：规则、服务器、用户总限速和突发都不生效，不进入计量、流量账本、规则配额、共享额度或套餐流量。结果是服务器之间（或到 Cloudflare）的线路能力，不等于经过规则和限速后的业务速度。
- 路径测速不经过入口规则的监听端口，也不经过多路径、MPTCP、TLS / WebSocket 等传输封装；末跳到业务目标只测 TCP 连接耗时，不测吞吐。
- 不测 UDP、丢包或抖动；目标的可用性见 [HEALTH.md](HEALTH.md)。
- 测速会真实占用两台服务器的带宽，测速期间业务流量可能变慢；云服务商可能对出站流量计费。

## 权限

| 操作 | 谁可以 |
| --- | --- |
| 服务器测速（`POST /speed-tests`） | 仅系统管理员；其他角色 403 |
| 路径测速（`GET`/`POST /speed-tests/path`） | 系统管理员，以及对路径上**每一台**服务器都有写权限的用户；只读角色 403，看不到规则或任一服务器的用户 404 |
| API 令牌 | 读取需要 `read`；开始、取消需要 `nodes:write` |
| 查看历史 | 系统管理员看全部；其他用户只看自己租户的路径测速 |
| 取消（`DELETE`） | 系统管理员；路径测速另允许对路径上每台服务器有写权限的用户 |

## 并发与冷却

- 每台服务器同一时间只参与一项测速；涉及正在测速的服务器时为 409 “server X is already running a speed test”。
- 非系统管理员两次开始测速至少间隔 1 分钟，未到时为 429 “wait N s before starting another speed test”。
- 每一段有截止时间（每段的硬超时再加 30 秒，末跳连接耗时 45 秒），到时没有结果的段记为失败并继续下一段，因此 Agent 失联不会让服务器一直处于“测速中”。

## 存储与审计

- 测速记录保存在控制器的元数据中（`speed_test:<id>`），不改数据库结构；正在运行的记录列在 `speed_tests_running`；保留最近 50 条已结束的记录。
- 每段的令牌单独保存在 `speed_test_token:<id>`，只下发给该段的两台 Agent，测速结束时删除；API 返回和审计日志中都没有令牌。
- 审计动作：`speed_test.start`（参数、服务器、规则）、`speed_test.cancel`、`speed_test.finish`（状态和各段平均速度）。
- 实时进度只在内存中，控制器重启后丢失；记录本身保留，未结束的段到截止时间后记为失败。

## 端口与防火墙

- 服务器 ↔ 服务器和路径测速需要对端（每一段的下一跳）在防火墙 / 安全组中放行**测试端口的 TCP 入站**。放行整个转发端口范围即可，因为自动选择的端口来自该范围；指定端口时只需放行该端口。
- 在 NAT 后的服务器上，转发地址和公网端口映射必须与实际一致，否则发起端连不上（显示连接错误）。
- 服务器 ↔ Cloudflare 需要服务器能以 HTTPS 访问 `speed.cloudflare.com`（TCP 443 出站）。
- 路径测速的连接耗时由末跳服务器直接连接业务目标，与业务连接相同。

## 同步协议与兼容性

与 0.145.0 反向隧道、0.147.0 分方向限速的做法相同：

- 控制器的每个同步回复带 `speed_test: true`（为 false 时省略）。只有收到它的 Agent 才在统计中回报 `stats.speed_test: {tasks?: [...]}`；控制器第一次收到时记录 `speed_test_node:<节点>`，`GET /nodes` 显示为 `speed_test_support`。
- 只有回报过支持的 Agent 才会收到 `SyncResponse.speed_test_tasks`（为空时省略）。每个任务是四种固定角色之一：`listen`（监听地址 + 令牌）、`dial`（`host:port` + 令牌）、`cloudflare`、`connect`（`host:port`）。Agent 停止控制器不再下发的任务。
- 控制器开始一段时通过 `GET /agent/watch` 的 `speed_tests_changed: true` 唤醒相关 Agent，使它们立即同步；测速进行中 Agent 每秒同步一次，任务结束时立即同步回报结果。旧 Agent 忽略这个字段。
- Agent 的回报有大小限制：最多 8 个任务，每个方向最多 4 条错误，每条错误有长度上限；超过时同步为 400。
- **旧 Agent（0.147.0 及更早）** 忽略未知的同步字段、从不回报支持，也收不到任务，原有功能不受影响；涉及它的测速返回 409 “the agent on server X is too old for speed tests; upgrade it first”。从未连接过面板的服务器返回 409 “server X has not connected to the panel yet; …”，离线超过 90 秒的服务器返回 409 “server X is offline”。
- **新 Agent 对 0.147.0 控制器**：旧控制器不发 `speed_test`，新 Agent 不回报 `stats.speed_test`（旧控制器的 `EngineStats` 拒绝未知字段），也没有任务可运行。
- 升级顺序与以往相同：先升级控制器，再升级 Agent。

## 界面

- **诊断报告 → 测速**（系统管理员）：选择方式（服务器 ↔ Cloudflare、服务器 ↔ 服务器）、服务器、方向、时长或数据量、并行流数和对端测试端口，开始 / 取消，显示实时进度，以及最近 50 次测速的历史。
- **转发规则 → 按服务器** 的规则操作和 **全部转发** 的路径操作中有“路径测速…”，打开对话框显示路径、参数、不受限速 / 不计量的说明、路径上的限速、每段结果和最慢的一段。
