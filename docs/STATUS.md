## 下一轮优先顺序

1. 合并提交已降低控制器同步开销；继续优化补额调度、测量慢控制链路和公平性，再推进异常预留回收、周期调度、分布式身份租约、日志归档/异地存储和密钥迁机。已覆盖子进程突然退出的四个持久化边界；真实断电与双端丢失仍须专门验收。
2. PROXY protocol 已在 0.7.0 接入，继续跨节点多跳图模型；端口段、DNS TTL 缓存、出口绑定及节点内环路保护已有本地实现与测试，继续补 Linux 路由、外部 UDP/TLS 互通和浏览器验收。
3. 继续 WS/WSS、安全隧道协议、证书自动化与节点凭据轮换；现有 TLS 不能代替完整安全传输模块验收。
4. 在两台 Linux 节点上验收部署与网络能力，增加实际线路、并发连接和长时间负载基准。
5. 按完整清单继续多跳、选路、聚合、组网、商业与共享功能，保持统一身份和账本模型。

## 0.3.0 本轮进展

- 用户、租户和节点总额度通过服务端自动绑定规则；预留发放、累计消费和归还保持数据库事务边界，重复消息不会重复扣量或退款。
- 两个真实 Agent 同时消耗同一用户额度；TCP 连续补额保持数据完整，UDP 离线仅消费已预留部分，恢复后继续补额，4 KiB UDP 包可跨越 64 字节预留批次限制而不被拆包。
- 保留在途 TCP 缓冲，使用阈值触发补额；累计消费不再每次扫描全部历史，已耗尽预留从可用集合移出，无全局额度的规则跳过额度查询。
- 重启不复用旧运行预留；控制器备份恢复后暂停新额度分配。未知消费边界不自动归还，代价是可能保守占额。解除恢复隔离尚无接口，不能把这项保护称为完整恢复。
- 管理 API 和页面增加共享额度创建、调整、已用/预留/未分配展示。正常停止补报最后用量；TLS 测试材料改用标准 PKCS#8 生成，排除本机旧版 LibreSSL 短标量编码导致的偶发失败。
- 独立额度测试、真实网络测试及基准入口已加入；最终检查结果和限制统一见 `VALIDATION.md`，所有 22 模块继续保留。

## 0.4.0 本轮进展

- 控制器默认记录独立恢复日志与原子进度清单；旧数据库备份可通过完整日志恢复后续节点身份、权限、会话、配置、预留、用量与审计。CLI 恢复只写入新目录，校验失败保留原输入。
- 写入按准备日志、数据库事务、提交日志和清单依次确认；故障后拒绝进一步写入。系统管理员可读取恢复状态，健康检查在日志故障后返回 503，管理页面有对应状态入口。
- 四个持久化边界分别通过真实子进程突然退出验证。另测日志损坏、截断、无关日志、缺少清单、清单写入失败、旧状态重新绑定拒绝，以及旧备份恢复后同一 TCP 连接继续补额。
- 修复有序停止时丢失预留回复造成的保守占额：结算找回已发额度，取消未发请求，较晚到达的原请求也不能重新分配。规则删除后仍能结算未确认请求。
- 自动化测试增加到 68 项；另有一个标为 ignored 的崩溃子进程入口，由父测试显式执行四次，不属于跳过验收。Release CLI 恢复演练和新基准见 `VALIDATION.md`。
- schema v4、同步新增字段要求控制器与 Agent 协调升级；构建增加 libclang 依赖。当前日志无轮换/异地复制，同步回退日志与清单不能证明新鲜度，异常节点未知消费仍不可自动退款。
- 本机共享额度基准发现显著性能回退：4 MiB 预留、8 总连接约 0.32 Gbps，32 MiB 预留约 2.97 Gbps。严格逐事务日志同步是主要待优化点；此版不标记性能验收通过，原始数据和诊断边界见 `VALIDATION.md`。

## 0.5.0 本轮进展

- 节点同步使用有界队列，最多等待 2 ms 合并 16 项；64 项等待队列满时返回 429。每项独立验证和回滚，存储故障中止整批，全部持久化成功后才响应；没有放大预留粒度或省略同步屏障。
- 增加管理员同步统计与页面展示；worker 空闲时不保留数据库强引用，避免关闭服务后仍占用恢复日志锁。用量查询增加同毫秒记录的稳定排序。
- 5 项新回归覆盖混合有效/无效请求、旧备份重放、重复请求、整批存储/日志失败、响应归属、指标权限、128 路请求拥塞与重试。合计 73 项测试通过；Release 恢复演练仍精确核对 286,720 字节。
- 同一二进制下，32 个模拟节点的控制 API 中位处理率从约 52.8 提升到 342.1 请求/秒，160 个测量请求由 160 次提交降到 15 次。它是控制面基准，不是 32 节点转发性能。
- 真实两 Agent 本机回环：4 MiB 预留、8 总连接，从关闭合并时约 0.322 Gbps 提升至约 1.277 Gbps；32 MiB 预留约 4.412 Gbps。不同配置的转发样本按顺序运行，尚未隔离全部系统负载；小批次仍有明显开销，性能最终验收未完成。
- schema v4 与 0.4.0 日志/节点协议保持不变。完整 22 模块、Linux/WAN、浏览器点击、长时压力和分布式恢复的缺口继续保留。

## 0.6.0 本轮进展

- 单规则支持最多 256 个连续端口，固定目标端口或偏移映射；不同入口共用规则额度、带宽桶和 TCP/UDP 会话上限。全节点最多 4096 个监听，全部新监听准备成功后才提交配置。
- TCP/UDP 业务出口可绑定源 IP、网卡或两者；实际创建套接字预检，拨号时仍执行绑定，失败没有自动选路回退。macOS 回环测试覆盖两个地址族；Linux 具体网卡权限与路由仍待实机验证。
- 可选 Hickory DNS 缓存遵守响应 TTL 与用户上限，支持负缓存与关闭正缓存，相同策略跨规则共享；真实测试改变 DNS 回答验证过期及地址族选择。未启用时继续使用操作系统解析。
- 节点内监听图拒绝字面量环路，拨号前检查 DNS 解析出的地址，活跃边随连接生命周期保留；旧连接结束前对新方向作保守拒绝。允许无环本机链。跨 Agent、NAT 和完整多跳拓扑仍未完成。
- 新增 16 项真实网络测试，累计 89 项通过；首次并行测试发现临时端口与出站连接竞争，已将测试监听选择移出常见临时端口范围。管理表单和能力目录已接入，视觉与点击未验收。
- IPv6 监听明确只接收 IPv6；双栈应创建两个监听。旧字段默认兼容，schema v4 和恢复日志格式不变；0.5 Agent 会拒绝新字段，先升级节点再发布新功能。
- Release 构建、实际 CLI、恢复与本机性能证据统一见 `VALIDATION.md`；没有宣称全功能完成或性能领先参考产品。全部 22 模块及原有发布门槛继续保留。

## 0.7.0 本轮进展

- 实现 TCP PROXY v1/v2 和逐包 UDP v2，入口必须明确配置可信实际对端；声明的来源随后用于 ACL 与来源哈希。IPv4 映射 IPv6 在 ACL/哈希中统一处理，原始地址族仍保留于报头。
- TCP 报头可位于 TLS 之前或加密连接内部；mTLS 和服务器名检查保持有效。入口报头及握手共用截止时间，报头不进入应用计量和限速；CRC32C TLV 独立校验，其余 TLV 不透传或用于认证。
- UDP 会话同时绑定实际对端、实际目的地址和原始声明，避免多个客户端/代理的回复混淆。Linux/macOS 通配监听通过内核 packet-info 获取实际目的地址，回复采用该源地址；macOS IPv4/IPv6 已验证，其他系统通配 UDP 明确拒绝而具体 IP 可用。
- 新增 19 项协议与网络测试，以及 1 项 HTTP 发布到真实 Agent 的测试，累计 109 项。复查另外复现了同一 PROXY 策略在两个目标之间移动时漏撤销旧会话的问题，现按目标地址检查策略变更，该回归测试已通过。
- 与本地独立构建的 HAProxy 3.0.30 完成 18 种双向 TCP 互通组合，核对 IPv4/IPv6 原始地址、二进制负载、半关闭和独立 CRC32C；实际账本为 294,912 字节且未计入报头。HAProxy 未链接进平台，也不包含于源码包。
- API、Agent、CLI 与页面表单均接入新字段，另附两跳 TCP/UDP 示例。页面只有源码与语法检查，视觉/点击未验收。schema v4 和恢复日志不变，0.6 Agent 应先升级再发布新字段。
- Release CLI、旧备份恢复和当前二进制的本机回环基准见 `VALIDATION.md`。新协议功能测试不等于协议性能、广域网或 Linux 验收。两连接共享额度首轮约 0.366 Gbps；按新版→旧版→新版追加 5 轮诊断约 0.345→0.371→0.605 Gbps，原始样本全部保留，性能稳定性仍待优化。完整 22 模块及所有后续门槛继续保留。
