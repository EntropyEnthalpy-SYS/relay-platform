## 下一轮优先顺序

1. 在分层额度基础上补异常预留回收、周期调度、身份租约、旧控制器额度恢复、旧配置/身份恢复及密钥迁机，并补真实崩溃和断电测试。
2. 完善本地路由环路检查、DNS 缓存、出口绑定与 PROXY protocol；保持“无法执行则拒绝配置”的契约。
3. 继续 WS/WSS、安全隧道协议、证书自动化与节点凭据轮换；现有 TLS 不能代替完整安全传输模块验收。
4. 在两台 Linux 节点上验收部署与网络能力，增加实际线路、并发连接和长时间负载基准。
5. 按完整清单继续多跳、选路、聚合、组网、商业与共享功能，保持统一身份和账本模型。

## 尚未通过的发布门槛

- Linux 实机和两节点部署；当前环境只有 macOS 验证。
- 管理界面的视觉与点击验收：浏览器权限检查拒绝了本机地址访问，没有绕过此限制。
- 同条件 Realm 基准、真实广域网、万级/十万级连接、72 小时混合负载。
- 额度完整灾难恢复、异常预留恢复、全局速率、控制面高可用，以及上述未完成模块。总流量额度与受管旧备份计量对账已通过本地测试。

部署模板、界面源码和功能目录不等于这些验收已经通过。不得把此开发版本标成全功能最终版。

## 0.2.0 本轮进展

- 新增 16 项测试，合计 44 项；覆盖真实 TLS 流量、mTLS 拒绝、证书轮换、旧节点/控制器备份恢复、1100 个历史周期、分页中断、配置端口占用和 v1 迁移。
- 同步协议要求 `ledger_id`，API 运行身份变化触发对账；v1 受管 Agent 升级时需要首次在线校准。
- 管理页面增加入口和逐目标 TLS 字段。浏览器交互仍未验收，不能把语法检查作为视觉与点击通过。
- 无 TLS 性能报告只描述本机回环；TLS 功能测试通过不代表已完成 TLS 压力基准。

## 0.3.0 本轮进展

- 用户、租户和节点总额度通过服务端自动绑定规则；预留发放、累计消费和归还保持数据库事务边界，重复消息不会重复扣量或退款。
- 两个真实 Agent 同时消耗同一用户额度；TCP 连续补额保持数据完整，UDP 离线仅消费已预留部分，恢复后继续补额，4 KiB UDP 包可跨越 64 字节预留批次限制而不被拆包。
- 保留在途 TCP 缓冲，使用阈值触发补额；累计消费不再每次扫描全部历史，已耗尽预留从可用集合移出，无全局额度的规则跳过额度查询。
- 重启不复用旧运行预留；控制器备份恢复后暂停新额度分配。未知消费边界不自动归还，代价是可能保守占额。解除恢复隔离尚无接口，不能把这项保护称为完整恢复。
- 管理 API 和页面增加共享额度创建、调整、已用/预留/未分配展示。正常停止补报最后用量；TLS 测试材料改用标准 PKCS#8 生成，排除本机旧版 LibreSSL 短标量编码导致的偶发失败。
- 独立额度测试、真实网络测试及基准入口已加入；最终检查结果和限制统一见 `VALIDATION.md`，所有 22 模块继续保留。
