# 本地验证记录

0.10.0 开发版通过 **158 项自动化测试**、Rust 格式检查、Clippy（警告视为错误）、JavaScript/Python 语法检查和 Release 构建。完整用例与日志见 [validation-evidence.json](validation-evidence-0.10.0.json)、[verification-0.10.0.txt](verification-0.10.0.txt)。全部 22 个目标模块继续保留，本版不是全功能最终版。

本轮增加真实目标回复探测、TCP/UDP 独立健康、过期排除、故障阈值和恢复观察、主备优先级、目标会话上限，以及健康 API/页面。合同见 [HEALTH.md](HEALTH.md)；成本/时延自适应、跨节点容量和完整路径质量仍未完成。

健康测试保留已建立 TCP，摘除失效 UDP 会话且不重放；验证目标移除再加入时旧连接仍占容量，失败配置不停止旧探测，32 个阻塞目标同时只运行至多 16 个探测。偏移端口独立检查，固定映射共享观测。控制器拒绝跨规则或重复报告时同项用量也不提交，并按读权限隔离其他租户。

端到端检查经过 mTLS WSS 与 TLS 内 PROXY v2，收到真正的应用回复；源节点探测应用量不进入业务账本，下游中转正常计量。最初测试错误地要求“零用量行必须存在”，修正为汇总源规则已有记录等于零，仍要求下游有正用量；没有放宽生产计量逻辑。测试中的一个存储方法名和 Clippy 风格错误也已修正。控制器结果过期测试仅改变测试库中的心跳时间，确认读取时显示 stale 而原始采样 JSON 不变。

[目标健康独立验证](health-smoke-0.10.0.json)运行两个 Python TCP/UDP 业务服务、一个控制器和一个独立 Agent。主服务 TCP 故障时 TCP 选后备，UDP 仍选主；UDP 随后故障时同一客户端 socket 的失效会话退出，新包选后备。恢复观察后新连接回到主目标；全部 TCP 目标故障时不接纳新的应用负载。恢复时已有健康 UDP 会话保留原目标，用新客户端验证新会话回切。

脚本从节点创建前的控制器备份重放 **12 个事务（3→15）**，核对旧登录会话、配置与用量、源备份/日志未改变。重新启动 Agent 前再次令主服务失效，Agent 根据新探测选择后备。包括后续 8 字节业务在内，健康规则 **673,185,856 字节**、普通规则 **673,185,792 字节**，合计 **1,346,371,648 字节**，节点与控制器精确一致。源节点主动探测没有混入业务账本。

[三节点链路验证](topology-smoke-0.10.0.json)继续运行三个独立 Agent，验证 TCP/UDP、WS、双向证书 WSS 三种链路、PROXY v2/CRC、方向反转、预览只读、事务发布与旧备份恢复。

| 节点间模式 | 每跳账本 / 字节 | 三跳合计 / 字节 | 重放事务 |
| --- | ---: | ---: | ---: |
| both | 69,152 | 207,456 | 29 |
| ws | 66,752 | 200,256 | 31 |
| wss | 66,752 | 200,256 | 31 |

三组共 **607,968 字节**精确匹配。每跳分别计量，不代表逻辑链路只收费一次；控制器一次提交期望状态不代表各节点同时激活。停止确认范围仍是整节点，0.10.0 还检查活跃探测为零。

既有功能也在此 Release 二进制下回归：

- [普通 CLI](cli-smoke-0.10.0.json)：TCP/UDP 合计 176 字节，备份账本一致。
- [端口段与绑定](cli-network-smoke-0.10.0.json)：两个连续偏移入口，127.0.0.1/lo0 出口，352 字节且共享一条规则账本。
- [PROXY 两跳](cli-proxy-smoke-0.10.0.json)：TCP/UDP 共 352 字节，不含报头。
- [HAProxy 互通](proxy-interop-0.10.0.json)：HAProxy 3.0.30、18 种双向 TCP v1/v2/CRC 与 IPv4/IPv6 原始地址组合，294,912 字节精确匹配。
- [独立 WS/WSS 互通](websocket-interop-0.10.0.json)：Python websockets 17.2，3 种成功组合和 7 个拒绝用例，1,573,086 应用字节精确匹配。
- [连续日志恢复](recovery-smoke-0.10.0.json)：7 个事务，旧 TCP 连接继续传输和补额；节点、控制器和预算均为 286,720 字节。

五个示例均经 Release CLI 校验，包含新增健康回显示例。测试与基准进程均已退出，没有安装系统服务或修改系统网络。

## 本机性能与实际限制

环境为 macOS 27.0.1、arm64、Apple M1 Pro、10 逻辑 CPU、32 GiB，Rust/Cargo 1.99.1、Python 3.14.4。基准在编译和功能检查结束后顺序运行。吞吐按单向应用字节除以整个往返验证时间计算，没有把双向字节翻倍计作好吞吐。

[健康选择测量](health-smoke-0.10.0.json)：每连接 16 MiB、1 MiB 预热、4 轮交替。一个受管 Agent 上两条相同优先级/容量配置的规则，只有一条启用健康检查；4 个 TCP/UDP 端点每 200 ms 探测。

| 并发连接 | 普通规则 / Mbps | 健康规则 / Mbps | 健康 / 普通 |
| --- | ---: | ---: | ---: |
| 1 | 4808.7 | 5614.0 | 116.7% |
| 4 | 10942.3 | 11090.2 | 101.4% |

两组测量期间后台探测都运行，结果主要比较业务选路路径，不能隔离“开关全部探测”的 CPU/网络消耗。健康组数值更高也不能据此声称探测加速；样本受运行顺序、回环与系统负载影响，不证明性能等同或生产容量。

[独立转发](benchmark-local-0.10.0.json)：无 TLS，每连接 32 MiB，直连与转发交替 5 轮，持久化账本 1,680,058,752 字节精确一致。

| TCP 连接数 | 直连 / Mbps | 转发 / Mbps | 转发 / 直连 |
| --- | ---: | ---: | ---: |
| 1 | 13261.2 | 4129.0 | 31.1% |
| 4 | 16109.4 | 11341.8 | 70.4% |

UDP 每包 1,200 字节、100 次、零失败；直连 RTT 中位 41.8 μs，转发中位 174.4 μs、P95 191.9 μs。具体 IP 监听，不是通配 packet-info 压力测试。

[两跳传输](benchmark-websocket-0.10.0.json)：同一 Relay 进程内两条计量规则，每连接 16 MiB、4 轮、逐轮轮换模式，没有全局共享额度。

| 并发连接 | 直连 / Mbps | TCP / Mbps | WS / Mbps | mTLS WSS / Mbps |
| --- | ---: | ---: | ---: | ---: |
| 1 | 13086.6 | 4116.7 | 3923.8 | 3315.6 |
| 4 | 15068.2 | 10014.6 | 9412.8 | 8032.0 |

三种转发模式各自的两条规则合计 1,346,371,584 字节，账本与备份一致。这是本机封装开销比较，不是跨机器容量或多路径收益。

[两 Agent 共享额度](benchmark-budget-0.10.0.json)：每连接 32 MiB、3 轮、4 MiB 预留，控制器日志开启，默认最多 16 项合并、等待 2 ms。

| 总连接数 | 无全局额度 / Mbps | 共享额度 / Mbps |
| --- | ---: | ---: |
| 2 | 4736.7 | 450.6 |
| 8 | 9704.4 | 1230.2 |

合计业务账本 **4,034,920,448 字节**，预算消费 **2,017,460,224 字节**；停止后未使用预留归零。625 个同步请求形成 427 次提交，实测最大合并 3 项，无队列满或失败批次。小预留批次下性能仍明显低于无全局额度组，需要继续优化控制/持久化路径。

旧版数据完整保留于 [0.9.0 验证](VALIDATION-0.9.0.md)及其版本化 JSON。0.9.0 的八连接相邻版本对照属于历史诊断，本轮没有重新执行；当前单连接或共享额度数字变化不能直接归因于健康功能，也不能宣称性能领先 Realm 或商业参考产品。

## 尚未通过的发布门槛

- Linux 实机、真实网卡与路由、Linux UDP packet-info。用户已有服务器，系统、架构和节点数量稍后提供。
- 浏览器视觉与点击验收：此前本机地址访问被权限检查拒绝，没有绕过；源码和语法检查不等于交互验收。
- 同条件 Realm 对照、真实 WAN、万级/十万级连接及 72 小时混合负载。
- 成本/时延自适应选择、跨节点容量、完整多路径与组网、运营交易等 [22 模块清单](REQUIREMENTS.md)中的剩余工作。
- 分布式身份互斥、异常预留回收、全局公平限速、日志异地存储/轮换、完整密钥迁移及灾难恢复。

数据库 schema v4 与日志格式不变。包声明 Rust 1.89，实际只验证了 1.99.1；先协调升级控制器/Agent，再启用新字段。此版本只提交本地开发与验证结果，完整目标继续进行。
