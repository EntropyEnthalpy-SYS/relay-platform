0.12.0 开发版通过 **176 项自动化测试**、Rust 格式检查、Clippy（警告视为错误）、JavaScript/Python 语法检查及 Release 构建。完整用例和运行记录见 [validation-evidence-0.12.0.json](validation-evidence-0.12.0.json)、[verification-0.12.0.txt](verification-0.12.0.txt)。本轮增加独立单连接聚合传输；完整 22 个模块与实机验收仍未完成。

## 本轮变更及直接证据

自有 relay-multipath-v1 通过双向 TLS 认证、随机会话和服务端令牌关联子流，开始屏障完成后只连接一次后端。支持分片、复制、上下行权重、逐子流出口绑定、会话容量、有限窗口、选择确认、断路重传和双向半关闭。公开格式、内存边界、计量及升级合同见 [MULTIPATH.md](MULTIPATH.md)。这是应用层流协议，不是 Linux MPTCP 或参考产品私有协议的兼容实现。

新增 15 项测试：7 项传输核心测试、6 项真实 mTLS/WSS 与配置集成测试、1 项拓扑排空测试，以及 1 项 Agent 最终同步测试。覆盖错误帧/确认、选择确认不能提前释放保留窗口、阻塞路径绕行、断路后保持同一连接、身份和令牌绑定、复制去重、方向限制、容量、策略撤销和健康探测。计量位于重组后的逻辑流，复制及重传额外负载另行展示。

Release 验证还暴露了有序停止时无待确认用量便直接退出、控制器保留旧活跃计数的问题。[修复前失败记录](regression-final-sync-before-fix-0.12.0.txt)来自本轮中间候选代码，并非已发布的 0.11.0 二进制。现在停止至少尝试一次最终同步；回归同时要求零活跃状态和之前的配置应用错误被保留。两秒清理期限内控制面不可达时，不能声称最终回报已送达。

## 单连接聚合实测

环境为 macOS 27.0.1、arm64、Apple M1 Pro、10 逻辑 CPU、32 GiB，Rust/Cargo 1.99.1、Python 3.14.4。编译和完整测试结束后单独运行性能脚本，没有让编译或其他性能脚本并发干扰。

[原始聚合结果](benchmark-multipath-0.12.0.json)由实际控制器、两个独立 Agent、mTLS 和两个独立 Python 限速代理产生。每条路径每方向上限分别配置为 2 MiB/s 与 1 MiB/s；单路径组只走快路径。三种模式轮换顺序，预热各 256 KiB，再以一个应用 TCP 连接传输 4 MiB、测量三轮。好吞吐采用单向已验证应用字节除以完整往返耗时，没有把两个方向相加翻倍。

| 模式 | 子流数 | 中位好吞吐 / Mbps |
| --- | ---: | ---: |
| 单快路径 | 1 | 13.37 |
| 双路径分片 | 2 | 21.10 |
| 双路径复制 | 2 | 11.87 |

本次分片与单快路径之比为 **1.578**，约提升 **57.8%**，达到脚本预先设定的超过 15% 的观察阈值。三轮分片为 21.18、21.10、20.80 Mbps；每轮快慢子流上行约 2.77 MB 和 1.48 MB（包含 TLS 与聚合封装），权重通过未确认负载与可写状态影响分配，不承诺精确 2∶1 字节比例。

这是软件限速回环下的结果。Python 每块休眠的定时和调度开销会降低实际可用速率，单路径和多路径不一定受同样比例影响，因此 57.8% 不能解释成真实线路固定提升、超过物理带宽上限或最大性能。两子流位于同一台机器，也不证明多 WAN 路由独立。

额外测试在业务已传输 128 KiB 后切断快子流；同一个应用连接的 4 MiB 内容全部校验通过。六条规则的上下行账本总计 **170,917,888 字节**，Agent 与控制器完全一致。两端各报告 **12,845,056 字节复制负载**；故障与测量合计重传分别为 8,339,456 和 8,978,432 字节，保留这些额外开销，不将其算作有效业务吞吐。

发送保留窗口峰值均为 1,048,576 字节；接收重排峰值分别为 49,152 与 360,448 字节，未超过本次 64 帧窗口。正常结束后两端活跃聚合会话与子流均为零，各记录一次断路。窗口指标不是整个进程的 RSS 或网卡流量。

两个较早候选结果也保留：[选择确认之前](benchmark-multipath-candidate-before-selective.json)的分片/单路径为 15.67/14.35 Mbps（1.092 倍）；[调整发送队列调度之前](benchmark-multipath-candidate-before-weighted.json)为 15.25/13.01 Mbps（1.172 倍）。后者单看比例提高，但绝对分片速度没有改善，且路径分配接近平均。本轮随后修正短暂队列满时的权重失效，并用阻塞路径测试约束等待期限。前两份记录是不同 SHA 的未提交中间候选，不是当前 Release 的验收结果，也不是控制系统负载后的严格因果实验。

## 剩余发布门槛

- 两台 Linux 实机、实际网卡/路由与 Linux UDP packet-info；用户已有服务器，系统、架构、节点数稍后提供。
- 浏览器视觉与点击：此前本机地址权限检查拒绝，未绕过；仅源码与语法检查通过。
- 真实 WAN、不同延迟/丢包、同条件竞品对照、万级/十万级连接和 72 小时混合负载。
- 聚合自动补建子流、延迟自适应、独立服务端互通、持久历史观测，以及 Linux 内核 MPTCP。
- 异常预留回收、分布式身份租约、全局公平限速、日志异地存储/轮换、密钥迁移与完整灾难恢复。
- [全部 22 模块](REQUIREMENTS.md)中的多协议、组网、运营交易、订阅、DNS、资源共享与其他未完成项；持续状态见 [STATUS.md](STATUS.md)。
