# 本地验证记录

0.15.0 开发版通过 **210 项自动化测试**、Rust 格式检查、Clippy（警告视为错误）、JavaScript/Python 语法检查与 Release 构建。完整用例见 [validation-evidence-0.15.0.json](validation-evidence-0.15.0.json)，日志见 [verification-0.15.0.txt](verification-0.15.0.txt)。本轮接入节点资料与真实暂停/到期；完整 22 模块、Linux 实机与浏览器验收仍在推进。

## 节点资料与生命周期

新增 11 项自动化测试：7 项资料存储测试、1 项时间前跳/回拨测试和 3 项真实 HTTP/Agent 测试。覆盖字段边界、精确整数成本、旧节点兼容、过滤、租户权限、并发编辑唯一胜出、批量冲突/存储失败回滚、完整日志恢复，以及资料编辑不重建连接、暂停和到期真实停止。

独立 [Release 进程验收](node-profiles-smoke-0.15.0.json)使用两个节点资料记录、一个实际转发节点，以及先后启动的真实 Agent：

- 类型、分组、标签和备注查询匹配，成本 **12,500,123 百万分之一货币单位**精确保存。已有 TCP 连接在资料修改后继续传输，转发配置始终为第 1 版。
- 旧资料修订被拒绝；批量第二节点冲突时第一节点也不修改。成功保存返回两份节点修订回执。
- 暂停后约 **0.46 秒**退出，已有 TCP、监听和 UDP 均关闭。节点、控制器及预算结算为 **448 字节**，已知未使用预留归还。
- 重新允许并设置到期时间后，先观测到租约已按到期截短，再停止控制器并继续 TCP/UDP。监听关闭观测比到期早 **468 ms**；到期后的原状态重启被 HTTP 410 拒绝。
- 清除到期后，按冷启动保留期等待约 **5.13 秒**，取得第 3 代所有权，并核对原状态预留，补报 **160 字节**。继续业务后，三份账本最终均为 **1,216 字节**，预算已承诺量等于实际消费。
- 从资料修改前的旧控制器备份重放 **25 个事务**，逐字段核对名称、资料修订、成本、分组、暂停/到期设置和转发修订，累计用量仍一致。所有临时进程退出。

复查发现未发布候选在“暂停时改早到期，立即重新允许运行”的组合下漏检了旧授权窗口。先用新增断言[复现失败](regression-node-reenable-before-fix-0.15.0.txt)，再让重新允许状态执行相同截止时间检查。批量保存逐节点采样当前时间，不使用批次开始时间推算后续节点的已授期限。

首轮独立脚本将 UDP 客户端队列中的系统错误误当成数据回复；修正后记录的两次停机观测均为 ConnectionRefusedError，没有 UDP 业务回包。原始失败属于测试辅助判定，运行程序没有为通过该检查放宽停止要求。

API、整数口径、时间假设、离线节点限制和升级步骤见 [NODE_MANAGEMENT.md](NODE_MANAGEMENT.md)。类型和成本仍是管理资料，不自动配置 NAT 或参与选路。暂停按已授窗口收敛；单机测试不证明真实系统冻结、错误系统时钟、跨主机故障或完整身份生命周期已经验收。

## 本机性能回归

环境为 macOS 27.0.1、arm64、Apple M1 Pro、10 逻辑 CPU、32 GiB；Rust/Cargo 1.99.1、Python 3.14.4。编译、完整测试结束后，16 组 Release 验收及基准顺序运行，各性能脚本没有相互并发。最低声明 Rust 1.89 尚未验收。没有做同条件竞品或版本间因果对照。

[独立转发](benchmark-local-0.15.0.json)：无 TLS，每连接 32 MiB、5 轮；账本 1,680,058,752 字节一致。

| 连接数 | 直连 / Mbps | 转发 / Mbps |
| --- | ---: | ---: |
| 1 | 13346.8 | 4792.4 |
| 4 | 15101.7 | 11398.8 |

UDP 每包 1,200 字节、100 次、零失败；转发 RTT 中位 172.7 μs，P95 191.4 μs。

[两 Agent 共享额度](benchmark-budget-0.15.0.json)：严格节点、每连接 32 MiB、5 轮、4 MiB 预留，恢复日志开启，最多合并 16 项、等待 2 ms。

| 总连接数 | 无全局额度 / Mbps | 共享额度 / Mbps |
| --- | ---: | ---: |
| 2 | 5079.6 | 661.9 |

节点与控制器均为 6,719,275,008 字节，预算消费 3,359,637,504 字节，正常停止后未使用预留为零。1,033 个同步请求形成 596 个批次，最大合并 3 项；零提交失败、零拥塞退回，所有节点零计量失败、零额度超时、最终零等待。共享额度仍有明显吞吐开销，本轮没有性能优越性结论。

## 单连接多路径回归

[聚合原始结果](benchmark-multipath-0.15.0.json)使用实际控制器、两 Agent、mTLS 和两个 Python 限速代理。路径每方向配置 2 MiB/s 与 1 MiB/s；每轮一个应用连接传输 4 MiB、测量三轮，轮换模式。好吞吐为单向已校验应用字节除以完整往返耗时。

| 模式 | 中位好吞吐 / Mbps |
| --- | ---: |
| 单快路径 | 14.27 |
| 双路径分片 | 21.66 |
| 双路径复制 | 12.04 |

本次分片与单快路径比为 **1.517**，约提高 51.7%，达到脚本预设的超过 15% 观察阈值。业务中切断快子流后，同一应用连接全部内容校验通过。六条规则账本合计 170,917,888 字节一致；额外复制与重传开销保留在原始报告，结束后活跃会话及子流归零。

该结果仅代表软件限速回环。Python 定时/调度、同机资源与路径配置影响结果；不能推定真实 WAN 增益、独立物理路由、最大吞吐或比其他产品更快。上一版原始记录保存在 [0.14.0 验证](VALIDATION-0.14.0.md)。
