# 本地验证记录

0.5.0 开发版通过 **73 项自动化测试**、Rust 格式检查、Clippy（警告视为错误）、JavaScript/Python 语法检查与 Release 构建。逐项测试、源码指纹和二进制校验值见 [validation-evidence.json](validation-evidence.json)，日志见 [verification-0.5.0.txt](verification-0.5.0.txt)。

本轮合并控制器同步提交，保留原来的恢复确认顺序。控制 API 处理率和真实转发吞吐均有改善，但小批次补额仍有明显开销；全功能和最终性能目标尚未完成。

## Release 恢复演练

[实际 CLI 演练](recovery-smoke.json) 在创建节点前备份，随后注册身份、发布规则、领取额度并转发。原控制器停止期间继续使用已有预留；CLI 重放旧备份后启动新控制器，同一 TCP 连接继续传输并申请新额度。

重放 7 个事务，从序号 4 到 11。节点、控制器和额度记录均为 **286,720 字节**，停止后没有未用预留；原备份和日志未修改，旧会话与节点配置恢复。另行独立 TCP/UDP CLI 探测为 176 接纳字节、备份一致，见 [cli-smoke.json](cli-smoke.json)。所有验证子进程已停止。

## 控制 API 合并对比

[benchmark-control-sync.json](benchmark-control-sync.json) 使用同一个 Release 二进制启动两个临时控制器，分别设为每批 1 项和最多 16 项。每个控制器有 32 个模拟节点，预热后交替发送 5 轮同步；每组测量 160 请求。只上报合成的递增一字节计量，不启动 Agent，也没有业务流量。该结果描述控制 API 处理能力。

| 配置 | 中位请求/秒 | 请求延迟中位 / ms | 请求延迟 P95 / ms | 测量期日志提交数 |
| --- | ---: | ---: | ---: | ---: |
| 逐项提交 | 52.8 | 314.2 | 576.0 | 160 |
| 默认合并 | 342.1 | 60.3 | 92.0 | 15 |

每组累计合成账本为 192 字节，全部请求得到对应节点与序号的确认。默认合并处理率约为逐项提交的 **6.48 倍**，每次日志提交平均覆盖 10.67 请求；没有队列拒绝或提交失败。它不能换算成 32 台服务器的转发吞吐。

## 真实两个 Agent 的额度吞吐

同一二进制、同一台 macOS 主机，临时控制器始终启用严格恢复日志。两个实际 Agent 共享用户额度，另两个无全局额度 Agent 作为参考；分组交替，只有被测组传输。每连接 32 MiB、3 轮，中位吞吐按两个节点合计单方向应用字节计，所有载荷逐字节验证。合并开/关样本分次运行，未隔离全部系统负载。

| 控制提交 | 单次预留 | 总连接数 | 无全局额度 / Mbps | 启用额度 / Mbps |
| --- | --- | ---: | ---: | ---: |
| 关闭合并 | 4 MiB | 2 | 4596.6 | 307.6 |
| 关闭合并 | 4 MiB | 8 | 9780.6 | 322.1 |
| 默认合并 | 4 MiB | 2 | 4681.2 | 641.9 |
| 默认合并 | 4 MiB | 8 | 9271.9 | 1277.0 |
| 默认合并 | 32 MiB | 2 | 5477.4 | 2673.0 |
| 默认合并 | 32 MiB | 8 | 10714.1 | 4412.0 |

4 MiB、8 连接：从 322.1 到 1277.0 Mbps，约 **3.96 倍**；单次预留大小相同。32 MiB 批次减少补额次数，但增加失联后的保守占额，不能将它与 4 MiB 当作同一种资源配置。合并没有删除任何日志同步屏障。

每次完整基准的节点与控制器账本均为 **4,034,920,448 字节**；预算组 **2,017,460,224 字节**，正常停止后未用预留为 0。默认 4 MiB 样本处理 609 次同步、完成 346 个批次，最大单批 3 项；关闭合并是每批 1 项。数据见 [关闭合并](benchmark-budget-individual.json)、[默认 4 MiB](benchmark-budget.json)、[默认 32 MiB](benchmark-budget-32m.json)。

小批次吞吐仍明显低于无全局额度转发，慢控制链路、单节点极限和公平性未验收。下一步继续补额调度与控制器存储开销分析。已有改善不等于性能领先参考产品。

## 独立转发回环

环境为 macOS arm64、Apple M1 Pro、10 逻辑 CPU、32 GiB 内存、Rust/Cargo 1.99.1。无 TLS、Python 回显目标；每连接 32 MiB、5 轮，直连与转发交替。见 [benchmark-local.json](benchmark-local.json)。

| TCP 连接数 | 直连 / Mbps | 转发 / Mbps | 转发 / 直连 |
| --- | ---: | ---: | ---: |
| 1 | 14638.4 | 5044.9 | 34.5% |
| 4 | 15403.5 | 11268.4 | 73.2% |

UDP：1200 字节、100 次、0 失败；直连 RTT 中位数 39.9 μs，转发 177.7 μs，转发 P95 209.2 μs。接纳量与账本均为 **1,680,058,752 字节**。这些数值不代表 WAN 或 TLS 压力表现。

## 验收边界

- 管理页面和 API 已更新，但本机浏览器访问未获授权，视觉、点击和移动端布局没有验收。
- 无两台真实 Linux 节点、广域网、同条件参考产品基准、万级连接或 72 小时混合负载。
- 未执行实机断电、异地存储或整盘损坏演练；节点未上报且已丢失的数据不能重建。
- 日志轮换、异地复制、分布式身份租约、异常预留恢复、周期调度、全局速率、公平分配和密钥迁移未完成。
- TLS 功能测试与压力测试分开。macOS UDP 覆盖最大 8192 字节，Linux 60000 字节分支仍未执行。
- 完整目标仍见 [REQUIREMENTS.md](REQUIREMENTS.md) 与 [STATUS.md](STATUS.md)，没有任何完整大模块因本轮优化而宣告全部验收。

旧版证据保留在带版本后缀的文件和源码包中；`VALIDATION-0.4.0.md` 记录上一轮性能回退及诊断，旧相对链接应结合对应版本的 JSON 阅读。
