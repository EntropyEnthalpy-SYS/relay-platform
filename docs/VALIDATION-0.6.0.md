# 本地验证记录

0.6.0 开发版通过 **89 项自动化测试**、Rust 格式检查、Clippy（警告视为错误）、JavaScript/Python 语法检查和 Release 构建。记录见 [validation-evidence.json](validation-evidence-0.6.0.json) 和 [verification-0.6.0.txt](verification-0.6.0.txt)。完整目标尚未完成。

本轮新增端口段、出口 IP/网卡绑定、目标 DNS TTL 缓存与同一 Engine 内的监听环路检查。字段、升级语义及边界见 [ROUTING.md](ROUTING.md)。

## 功能验证

| 组 | 通过数 | 主要覆盖 |
| --- | ---: | --- |
| 跨节点额度 | 12 | 层级额度、幂等、整包、并发、恢复隔离、归还和迟到消息 |
| 控制与 Agent | 12 | 真实 HTTP 同步、两 Agent 额度、控制器替换、离线和恢复 |
| 原转发引擎 | 16 | TCP/UDP、IPv4/IPv6、半关闭、ACL、均衡、限速、额度和配置失败 |
| 新网络能力 | 16 | 端口范围/偏移、共用额度与连接数、占用回滚、IP/网卡绑定、TTL/负缓存/零 TTL、地址族、静态/动态环路、旧连接保护、IPv6-only |
| 控制器日志 | 6 | 重放、损坏/截断/缺失拒绝、故障后拒写、状态与权限 |
| 账本与模型 | 8 | 用量、周期、租户、身份、配置修订及备份 |

| TLS | 7 | TLS 1.2/1.3、mTLS、错误证书拒绝、无明文回退及更新 |
| 突然退出 | 1 | 四个持久化边界启动真实子进程突然退出再恢复 |

另有一个 ignored 的崩溃辅助入口，由父测试显式执行四次，未计为独立通过项。未进行实机断电验证。

网络测试使用真实本机套接字及可变回答的 DNS 服务。验证了 1 秒响应 TTL、30 秒响应被配置上限缩短、NXDOMAIN 负缓存过期、0 秒禁用正缓存，以及 DNS 由正常回显地址变为本机监听时被阻止。相同配置跨规则共享缓存；IPv4/IPv6 地址选择和实际目标观察到的源 IP 均有检查。

旧配置中的 A→B 连接仍存活时，新方向 B→A 被保守拒绝；旧连接正常转发并结束后，新无环方向可以使用。此项没有扩大为跨 Agent 或 NAT 环路保证。

首次并行网络测试发生测试监听端口与临时出站端口竞争。已调整公共测试工具，在 12000..29999 中试绑定 TCP/UDP 选择监听地址；随后全套 89 项通过。没有放宽运行时端口冲突拒绝，也没有跳过失败测试。

## Release CLI 与恢复

[普通 CLI](cli-smoke-0.6.0.json)：TCP/UDP 各 44 字节往返，持久化接纳总计 176 字节，备份账本一致。

[新网络 CLI](cli-network-smoke-0.6.0.json)：两个连续入口按偏移分别转发至两个目标，同时设置 127.0.0.1/lo0 出口绑定和系统 DNS 缓存配置。两个入口分别通过 TCP/UDP 探测，共 352 字节，只有一条共享规则计量记录；备份与原账本一致。目标是 IP 字面量，因此 CLI 此项确认系统缓存配置可加载；实际 DNS 缓存行为由网络集成测试验证。

[恢复演练](recovery-smoke-0.6.0.json)：在节点创建前备份，随后通过实际 Agent 转发并消费额度。CLI 从旧备份重放 7 个事务（序号 4→11），恢复节点身份、配置及旧 API 会话。原 TCP 连接在控制器替换后继续传输和补额；节点、控制器和额度记录均为 **286,720 字节**。输入备份/日志保持不变，有序停止归还未用预留。所有验证子进程已停止。

## 本机回环性能

环境：macOS 27.0.1、arm64、Apple M1 Pro、10 逻辑 CPU、32 GiB 内存、Rust/Cargo 1.99.1、Python 3.14.4。以下本轮数据使用同一 Release 二进制、无 TLS、Python 回显服务。先完成编译/测试，再顺序执行基准；没有参考产品或广域网比较。

[独立转发](benchmark-local-0.6.0.json)：每连接 32 MiB，直连与转发交替，共 5 轮，中位值如下。所有载荷逐字节验证，持久化账本 **1,680,058,752 字节**完全匹配。

| TCP 连接数 | 直连 / Mbps | 转发 / Mbps | 转发 / 直连 |
| --- | ---: | ---: | ---: |
| 1 | 14821.9 | 5241.5 | 35.4% |
| 4 | 16089.8 | 11281.1 | 70.1% |

UDP 每包 1200 字节、100 次、0 失败；直连 RTT 中位 40.2 μs，转发中位 164.7 μs、P95 178.1 μs。

[真实两 Agent 共享额度](benchmark-budget-0.6.0.json)：每连接 32 MiB、3 轮；控制器恢复日志启用，最多 16 项合并提交、等待 2 ms；单次预留 4 MiB。无全局额度组也启用持久化规则计量。

| 总连接数 | 无全局额度 / Mbps | 启用共享额度 / Mbps |
| --- | ---: | ---: |
| 2 | 5237.7 | 585.2 |
| 8 | 9789.2 | 1254.2 |

节点与控制器账本合计 **4,034,920,448 字节**完全一致；预算组消费 **2,017,460,224 字节**，停止后未用预留 0。同步统计为 605 请求、319 批次、最大单批 3 项，无拥塞拒绝和失败批次。

小预留批次的全局额度仍显著降低吞吐。本轮数值不能证明“性能最强”，也没有隔离全部主机负载。0.5.0 的控制 API 合并开关对比与 32 MiB 预留结果保存在对应 `-0.5.0.json` 和 [VALIDATION-0.5.0.md](VALIDATION-0.5.0.md)；本轮没有重复这些对比，不能把旧数据标成 0.6.0 结果。
