# 本地验证记录

0.14.0 开发版通过 **199 项自动化测试**、Rust 格式检查、Clippy（警告视为错误）、JavaScript/Python 语法检查及 Release 构建。完整用例见 [validation-evidence.json](validation-evidence.json)，原始日志见 [verification-0.14.0.txt](verification-0.14.0.txt)。新增原状态额度恢复、只读预留明细和恢复诊断；完整 22 模块与 Linux 实机验收仍在进行中。

## 原状态额度恢复

本轮增加 12 项自动化测试：8 项存储/权限测试、4 项真实 HTTP/Agent 集成测试。覆盖连续所有权、丢失回复重试、层级待确认请求、备份移除资格、接替后拒绝复用、账本归属、消费上下界、事务失败、失败时不退款、租户隔离与 100/100/1 分页。

独立 [Release 强制终止演练](budget-recovery-smoke.json)使用真实控制器和 Agent 子进程，限制总额为 65,536 字节，租约为 5 秒：

1. 已确认初始 256 字节后停止控制器，在剩余租约内传输 TCP 和 UDP。Agent 持久化用量达到 24,832 字节，再用 SIGKILL 终止，退出码为 -9；其中 **24,576 字节尚未上报**。
2. 重启原控制器和原 Agent 状态。冷启动保留期内监听关闭，约 5.20 秒后取得第 2 代所有权，保持原预算 run_id，验证一份预留并补报至 24,832 字节。
3. 继续真实 TCP/UDP 传输到 **65,536 字节**总额。额外载荷被拒绝；正常停止后节点账本、控制器账本、预算消费与已承诺额度全部一致，开放预留为零。所有临时进程退出。

集成测试另行制造恢复事务已提交但回复丢失的情况，验证重复恢复不重复扣量、重试期间不开监听；恢复被拒绝时不退款，随后原状态可重新取得连续所有权再恢复。受管备份接替后，原状态必须采用新 run_id，原未知预留继续占额。

测试还用故意冲突的账本归属复现待确认预留缺少归属检查的候选缺陷；修复后完整验证通过。[失败记录](regression-budget-recovery-ledger-before-fix-0.14.0.txt)属于未发布的 0.14.0 候选，0.13.0 尚无此接口。另发现正常停止心跳会清空本次恢复诊断，先用现有 HTTP/Agent 用例的新增断言[复现失败](regression-budget-recovery-final-stats-before-fix-0.14.0.txt)，再保留完整停止快照；Release 演练也校验停机后记录不丢失。

恢复条件、顺序、备份区别及限制见 [BUDGET_RECOVERY.md](BUDGET_RECOVERY.md)。此结果不认证任意原始数据库复制、VM 快照回退或双端状态丢失；恢复标记不是快照新鲜度的密码学证明。租约到期和节点离线不触发自动退款。

## 本机性能回归

环境为 macOS 27.0.1、arm64、Apple M1 Pro、10 逻辑 CPU、32 GiB；Rust/Cargo 1.99.1、Python 3.14.4。编译、完整测试结束后，15 组 Release 验收及基准顺序运行，各性能脚本没有相互并发。最低声明 Rust 1.89 尚未验收。没有做同条件竞品或版本间因果对照。

[独立转发](benchmark-local.json)：无 TLS，每连接 32 MiB、5 轮；账本 1,680,058,752 字节一致。

| 连接数 | 直连 / Mbps | 转发 / Mbps |
| --- | ---: | ---: |
| 1 | 12683.3 | 4949.9 |
| 4 | 13919.9 | 11378.0 |

UDP 每包 1,200 字节、100 次、零失败；转发 RTT 中位 175.0 μs，P95 201.2 μs。

[两 Agent 共享额度](benchmark-budget.json)：严格节点、每连接 32 MiB、5 轮、4 MiB 预留，恢复日志开启，最多合并 16 项、等待 2 ms。

| 总连接数 | 无全局额度 / Mbps | 共享额度 / Mbps |
| --- | ---: | ---: |
| 2 | 4722.2 | 664.3 |
| 8 | 9741.6 | 1308.2 |

节点与控制器均为 6,719,275,008 字节，预算消费 3,359,637,504 字节，正常停止后未使用预留为零。1,018 个同步请求形成 632 个批次，最大合并 4 项；零提交失败、零拥塞退回，所有节点零计量失败、零额度超时、最终零等待。共享额度仍有明显吞吐开销，本轮没有性能优越性结论。

[两跳传输](benchmark-websocket.json)：每连接 16 MiB、4 轮，模式轮换；每种转发模式均为 1,346,371,584 字节、备份一致。

## 单连接多路径回归

[聚合原始结果](benchmark-multipath.json)使用实际控制器、两 Agent、mTLS 和两个 Python 限速代理。路径每方向配置 2 MiB/s 与 1 MiB/s；每轮一个应用连接传输 4 MiB、测量三轮，轮换模式。好吞吐为单向已校验应用字节除以完整往返耗时。

| 模式 | 中位好吞吐 / Mbps |
| --- | ---: |
| 单快路径 | 14.42 |
| 双路径分片 | 22.06 |
| 双路径复制 | 10.20 |

本次分片与单快路径比为 **1.530**，约提高 53.0%，达到脚本预设的超过 15% 观察阈值。业务中切断快子流后，同一应用连接全部内容校验通过。六条规则账本合计 170,917,888 字节一致；额外复制与重传开销保留在原始报告，结束后活跃会话及子流归零。

该结果仅代表软件限速回环。Python 定时/调度、同机资源与路径配置影响结果；不能推定真实 WAN 增益、独立物理路由、最大吞吐或比其他产品更快。上一版原始记录保存在 [0.13.0 验证](VALIDATION-0.13.0.md)。
