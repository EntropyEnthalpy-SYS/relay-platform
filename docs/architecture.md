# 独立实现的架构决定

产品目标是自己的完整平台，功能基线来自已有《统一转发平台分析与开发方案》的 22 个模块。旧压缩包不作为代码基础；原有产品只是需求参考。这里的实现状态不代表全量产品已经完成。

## 可执行结构

- `relay server`：身份、节点、配置版本、用量账本、审计及管理 Web。控制服务不转发业务流量。
- `relay agent`：通过独立凭据同步配置、执行真实 TCP/UDP 转发并补报用量。
- `relay standalone`：本地配置和同一个转发核心，用于离线部署、排障和独立性能测试。
- 同一 Rust 类型定义连接 API、Agent 与执行层；严格拒绝未识别的配置字段。
- 第一版存储采用 SQLite WAL，限定单控制实例，便于本地验收及小规模部署。PostgreSQL、控制面高可用仍在完整范围内，在实现迁移与并发验收前不会标为支持。

## 配置与隔离

配置有 schema 版本、节点 ID 和递增修订号。控制面以期望修订号拒绝并发覆盖，保留历史。Agent 先验证并绑定新增监听，再持久化和激活；失败保留原版本。未变更的监听复用，现存连接按已选择目标继续；禁用、删除和计量周期变更需终止关联会话。每台节点只获取自己租户的配置。权限在服务端执行。

## 计量合同

用量单位为字节，不使用隐含 GB/MB 换算。一个计量周期由不可复用的 `meter_epoch` 明确标识。每条规则的上下行合并配额由所有 TCP 连接和 UDP 会话共同消费。

严格计量路径在转发前先把获准进入平台的应用负载写入本地事务，再转发。用量口径是“已接纳负载”，因此目标发送失败时也可能计费；运行统计另列真正写出的字节。这避免把物理发送和磁盘事务假装成可原子提交的一步。并发请求合并提交，不逐字节写数据库。磁盘失败时拒绝新增负载，保留已确认账。

0.19.0 起，未绑定共享额度（`budget_ids` 为空）的规则改用持久预留：转发前先在本地事务中预留一段字节（初始 4 MiB，转发速度超过补充时按倍数增长，最多 64 MiB），业务在内存中消费这段预留，不再为每个数据包或每次读取等待磁盘提交。已消费字节每 500 ms、配置变更、预留补充和正常停止时写入账本。进程异常终止后，下次启动把未释放的预留全部计为已用：用量可能多计最多 64 MiB，不会少计。受管节点从备份恢复时，先完成控制器分页对账，再只补记检查点未覆盖的预留部分。共享额度规则保持原逐次持久接纳路径。

节点上报每个规则和周期的累计上下行字节及单调序号。控制端验证归属、拒绝倒退或同序号变更，幂等确认；Agent 重启和重放不会重复累计。记录和凭据均受本地文件权限保护。删除规则保留历史账本与周期归属。

单节点规则合同继续适用。0.3.0 加入用户、租户、节点三个层级的全局流量额度，按独立预留分配至不同 Agent；共享资源和端口组、周期调度、全局速率仍需扩展。

## 性能与安全边界

异步网络、成熟 TLS 库、数据库和密码哈希采用公开依赖，具体版本由 Cargo.lock 固定。无商业产品激活依赖。自研密码算法不在计划内。生产跨机器控制通信须使用有效 HTTPS；本机 HTTP 只用于验收。

TCP 和 UDP 使用各自会话模型；UDP 有会话上限、有限队列（每会话最多 256 个数据报、256 KiB，排队超过 50 ms 的数据报丢弃并计入丢弃计数）和空闲回收。WS/WSS 封装和自有多路径流模块已接入；后续组网与内核 MPTCP 单独实现和验收。所有吞吐承诺须来自固定版本、硬件、协议和路径下的基准数据。

## 0.2.0：恢复与传输边界

SQLite schema v2 增加节点账本身份。受管节点从备份恢复时，先将控制器已确认的累计用量按稳定键分页合入，再激活配置；序号和上下行计量必须属于单调延续。恢复控制器时，进程身份变化触发节点重发已确认过的数据。完整分页完成前的状态写入是保守提高用量，恢复标记持久保存；中断不会重新开放旧额度。

本地文件锁保证同一路径的单进程实例。0.13.0 对严格节点增加单控制器执行租约：不同目录/机器的协作式 Agent 需要当前运行凭证才能对账、同步和运行，复制状态的新进程等待所有权。离线节点保留缓存运行、不提供跨机器互斥；两端都丢失的未确认数据仍无法恢复。完整预算异常恢复、多控制器共识及灾难恢复保留在范围内，见 [NODE_LEASES.md](NODE_LEASES.md)。

业务 TLS 使用 rustls + tokio-rustls，入口先完成认证再拨号目标；出口在证书链和服务名校验完成后才转发应用字节。每条方向保留原持久化接纳路径，按应用字节计量。依照 [tokio-rustls 的写入语义](https://docs.rs/tokio-rustls/0.26.6/tokio_rustls/)，转发在等待下一次应用读取前显式 flush，避免小请求长期停在 TLS 缓冲中。

证书和密钥通过本地编号选择，只有经过全部校验的配置才能替换当前运行状态。每次新修订重新读取启用规则的 TLS 材料；材料变化取消旧运行代次的连接。TLS 配置阶段拒绝明文回退、UDP 混用及任意路径引用。证书自动化、客户端身份细分、吊销与轮换工作流仍待实现。

## 0.3.0：跨节点额度边界

schema v3 引入独立的预算、预留和 Agent 待确认表。控制器在同一事务内更新已分配总量和唯一请求记录，维持 `consumed_bytes <= committed_bytes <= limit_bytes`。Agent 在同一事务内扣除所有适用预算与规则用量，任一层不足时不部分扣除 UDP；TCP 可接纳部分缓冲，之后继续补额。实际磁盘提交先于业务写入。

每次 Agent 进程启动生成新的运行 ID，旧的未封存预留标为 abandoned，不再花费或归还；因此旧磁盘副本不能再次消费相同预留，但不代表完整身份互斥已经实现。有序停止或所有业务会话空闲时先在本地封存，再向控制器归还剩余；请求/确认丢失后可幂等重试。消费完的预留也封存，避免可用额度查询随历史增长而扫描全部记录。

新增预算须先暂停所有受影响规则并确认配置，再由服务端绑定预算后重启。这个屏障避免旧配置继续无预算转发；删除规则但节点未确认不能绕过屏障。预算总额修改有修订校验，不能降低到已经承诺给节点的额度以下。

导出的控制器备份带新预算分配隔离标志；控制器遗忘的预留报告被拒绝，不能按旧快照余额再次分发。此阶段采用保守停止，尚无权威全节点恢复/解除隔离流程。普通断网时正在运行的 Agent 只能花费已有额度，严格节点还受剩余租约有效期约束；重启、周期切换和异常预留回收的可用性需要后续协议完善。更完整的操作语义和已知限制见 [BUDGETS.md](BUDGETS.md)。

## 0.4.0：连续恢复证据和停止结算

控制器默认用 SQLite Session 记录真实行变更，包括配置、身份和额度事务。每份准备记录带递增序号、前一条哈希和自身校验值；数据库检查点与业务数据在同一事务提交。只有日志准备、数据库提交、日志提交及原子进度清单都完成后，才确认写入。日志故障后拒绝新写入，重启依据原数据库检查点修复未完成边界。Agent 本地计量路径不启用此控制器日志。

恢复命令验证备份检查点在完整日志中，校验结构指纹、日志连续性和最新进度清单，然后在新目录严格重放；冲突即失败，完成后检查外键和数据库完整性。仅撤销备份工具额外写入的隔离标记，再恢复原有分配状态。日志与清单同时回退的情况无法由本地哈希证明最新性；此设计依赖保留最新文件，尚无远端复制、签名检查点或分布式控制器租约。

停止结算扩展了额度请求协议：`settle_only` 允许找回已经提交但回复丢失的预留，未提交的请求则持久化取消。即使原请求较晚到达也不会再分配。Agent 把找回的预留先封存，再幂等归还未消费部分；原请求先到和结算先到两种顺序都有回归测试。异常进程丢失的未知预留仍不退款。操作约束见 [RECOVERY.md](RECOVERY.md)。

## 0.5.0：节点同步合并提交

控制器将同时到达的节点同步请求放入有界队列，最多等 2 ms 收集 16 项；队列满时拒绝新请求并要求重试。worker 仅在处理批次时持有 Store；空闲等待不保留数据库强引用，关闭 API 不会因后台队列仍持有日志文件锁而阻止恢复。

同批请求在一份 LoggedTransaction 内按保存点顺序执行认证、用量和额度处理。输入/权限冲突回滚自身保存点，存储错误则中止整批；返回结果必须等数据库、日志和进度清单全部确认。该设计减少同时在线节点之间重复的存储屏障，不放大预留批次、不降低持久化级别。单节点请求仍承担完整提交成本。

管理员写入不经过该队列；Store 互斥锁使它们与同步批次串行化。没有引入多控制器并发或分布式事务。同步运行计数通过管理员诊断接口读取，端到端好吞吐与控制 API 请求率分别测量，不能相互代替。

## 0.9.0：声明拓扑与配置发布

规则是拓扑的唯一事实来源。下游声明可达端点，上游目标引用节点与规则，同时保留真实拨号地址；没有另一套可能与执行规则脱节的可编辑图表。图校验覆盖当前所有期望配置的候选快照，使用非递归有向无环检查，并验证租户、端点、端口范围与传输组合。它不解析 DNS，也不声称发现所有 NAT 或第三方代理别名。

预览只在一致的数据库视图上计算完整差异，不绑定规则身份或产生审计。发布在 Store 锁和单个 LoggedTransaction 内再次校验各节点 expected_revision，然后一并更新期望配置、绑定、历史及审计。单节点编辑和回滚复用相同路径，恢复日志将整批作为一个事务重放；不存在只恢复部分节点期望版本的成功结果。

Agent 分别轮询和准备运行状态，因此事务提交并不提供跨机器同时激活。拓扑路由变更采用先停止、确认、再发布的保守流程，避免方向反转时混用新旧声明边；当前需要整节点无活跃会话，换规则 ID 复用监听同样受到约束。离线状态、实例复制、物理别名和业务探测仍有明确边界，见 [TOPOLOGY.md](TOPOLOGY.md)。

应用流量沿用每跳独立规则账本与预算绑定，三跳会分别记录三份接纳量。逻辑流端到端计费、共享资源结算、健康选路和灰度任务需要另外建模，不能由拓扑图或配置回执推定已经实现。

## 0.10.0：主动观测与业务选择

探测器复用业务的出站连接准备流程，但使用独立、有界的并发和应用字节计数。每个映射端口/协议分别保存单调时钟观测，规则固定映射共享观测；配置成功提交后才启动新探测，准备失败不会取消旧运行状态。观察结果按阈值、过期和恢复窗口决定新业务目标是否可选。

目标会话计数挂在规则共享状态上，以目标地址字符串维护弱引用注册表，旧连接可跨目标删除/重加保持占用；每次接纳用原子操作预留容量。探测使用本地节点出站身份，不接纳用户业务，也不花费源节点业务额度；下游仍按实际收到的负载计量。已有 TCP 不被健康波动迁移，失效 UDP 会话退出且不重放。

控制器按实际配置修订验证健康报告，读取时根据心跳累计年龄，诊断不驱动预算退款或计费。主备优先级只在健康且未满的候选中应用原均衡策略；时延 EWMA 目前用于诊断，不作为自动最优路径算法。完整合同和限制见 [HEALTH.md](HEALTH.md)。

## 0.11.0：同步回执与运行诊断

一次控制回复中的本地用量确认与预留状态共享事务边界；非法授信或后续写入失败不能留下已确认用量，通知在提交和释放数据库锁之后发送。业务在查询可用额度之前构造更新等待对象，关闭“查询后、等待前已收到补额”的丢失通知窗口。预留身份、粒度、周期、计量和恢复保证不变。

计量线程池阶段、业务额度等待、控制器队列和存储阶段增加进程内采样。统计经现有同步和权限模型显示，只作诊断，不作为配额或计费权威；可观测范围、取消/失败口径及升级顺序见 [DIAGNOSTICS.md](DIAGNOSTICS.md)。

## 0.12.0：聚合流层

业务计量位于逻辑流，mTLS/WSS 子流位于其下。发送驱动保留有限窗口，接收驱动重排并广播累计确认/选择确认；复制不复制整份发送窗口，只共享不可变帧引用。组注册绑定实际 TLS 身份与随机令牌，子流保留原连接、目标容量和环路守卫；逻辑流释放时取消全部驱动，并由 Engine 的任务追踪等待清理。健康探测也建立真实聚合会话，源探测应用量仍单列。详细容量、关闭、计量和公开帧格式见 [MULTIPATH.md](MULTIPATH.md)。

## 0.13.0：节点执行所有权

单控制器持久化节点策略、运行编号、令牌哈希和所有权代数；单调截止时间留在内存。新所有者提交与旧回执清理共用事务，事务失败不发布新内存所有权。冷启动对已存在严格节点保留完整 TTL 等待，包含恢复到领取之前的旧备份。同步、对账和预算运行在写入前检查证明。

Agent 先取得当前所有权再修改预算运行和启动引擎；独立续租/监护避免控制请求卡住阻止到期退出。正常停止按引擎排空、账本结算、释放顺序执行，任务异常取消也会取消底层监听和连接。此机制不自动退款、不提供多控制器共识；具体时钟和外部后端边界见 [NODE_LEASES.md](NODE_LEASES.md)。

## 0.19.0：遥测历史

控制器在同步事务提交之后，把本次回报的转发字节、会话数、目标健康和 Agent 主机资源记成一个采样，并与同一节点的上一次回报比较，得出目标不可用/恢复、配置拒绝/恢复/应用和节点重新联系等事件。采样和事件只在内存中保存 1 小时，回滚的同步不会留下记录；离线事件在读取时按最后回报时间推出，因为沉默本身没有回报。这份历史只服务总览页，不影响选路、计量和恢复；字段与限制见 [API.md](API.md) 的“0.19.0 遥测”。


## 0.20.0：状态围栏、份额生命周期与重放域

用户速率份额现在按“仍在执行的规则”计算。控制器保存每个节点的期望修订和最后确认的应用修订；计算参与者时取两个修订配置中启用规则的并集，节点只有在成功应用新修订后才退出旧规则的份额。Agent 在应用失败时延续当前份额，而不是套用失败修订返回的列表。这样，保留旧配置确实同时保留其限速。

`advertise` 只是可达地址声明，不是“已计量上游”的证明。广告监听与普通入口一样参与份额，直接连接也会被限速。由于没有受信上游认证，多跳流量在每跳执行各自份额，链路吞吐可能低于份额之和；这是有意的保守取舍，后续共享计量模型需要独立协议。

Shadowsocks 的 TCP 盐缓存从“每个运行规则实例”提升为引擎内按（方式、密钥）共享。规则重建只有在加密身份改变时才获得新的重放域；名称、限速、健康策略等编辑沿用同一缓存。缓存只在仍被运行规则引用时保留。

持久状态围栏由两层组成：应用 schema `PRAGMA user_version` 从 4 升到 5（不改表，恢复日志格式 4 和 schema 指纹不变），以及 `relay build-info` 的控制器/Agent 状态兼容代号从 1 升到 2。0.18.0/0.19.0 在 `Store::open` 拒绝 schema 5；签名安装器拒绝跨代号回滚；`restore` 可重放 schema v4 备份并在输出上完成升级。围栏只对升级后的状态生效，部署顺序仍是先启动一次新控制器完成迁移。

## 0.21.0：客户端订阅

订阅记录和令牌索引存放在 metadata，避免再次改变应用 schema 或恢复日志格式。公开令牌是独立于登录会话和 API 令牌的 bearer 值，只保存 SHA-256 哈希；轮换通过一次事务替换记录和索引，旧令牌立即失效。渲染器以纯函数接收“节点名、节点标签、规则”候选，输出四种客户端格式；模板只保存显示选项，节点地址和规则内容在每次拉取时读取当前期望配置。普通 TCP/TLS/WS 规则没有客户端代理协议，必须在预览中显式跳过，不能伪装成受支持条目。

## 0.22.0：DNS 托管记录

DNS 服务商、区域和记录同样存放在 metadata，避免再改应用 schema；服务商令牌需要可逆保存，读取视图只暴露 `token_set`，并且整个 `/dns` 前缀只允许系统管理员会话。同步器把“本地期望记录”和“服务商返回记录”分开：`observe` 只产生差异动作，`apply` 才写入；记录按服务商 ID 或“类型+名称+relay 注释”匹配，外部同名记录不会被接管。控制器只记录服务商 API 已接受的状态，不把本地写入当作 DNS 传播成功。0.23.0 的记录还可绑定节点/规则健康门控；同步器读取节点 `stats_json` 中 `eligible && healthy` 的目标报告，并以 90 秒心跳作为新鲜度边界，失败时摘除、恢复时重建。

## 0.24.0：账号生命周期

密码、停用和删除都在一个 SQLite 事务中完成，并与会话/API 令牌撤销、审计记录同提交。本人改密保留当前会话哈希、删除其他会话；管理员重置和停用调用 `end_credentials` 删除全部会话与 API 令牌。删除账号前检查 `rule_bindings.owner_id` 和订阅 metadata，避免留下无主资源；最后一个活动系统管理员、自停用和自删除由服务端拒绝。

## 0.25.0：SOCKS5 入口

SOCKS5 握手在入口传输（PROXY/TLS/WS）之后、目标连接之前执行。解析器只接受 CONNECT，目标地址/IPv4/IPv6/域名的解析复用现有 resolver 与出口路由；连接成功后写成功回复，失败写状态 5，避免把连接错误伪装成成功。与 Shadowsocks 一样，规则没有固定目标，代理层只指定目的地；认证、来源 ACL、计量和限速仍由统一引擎路径执行。

## 0.26.0：公告

公告保存在 metadata，按租户或全局作用域、启用状态和开始/结束窗口过滤。租户管理员只能写本租户记录，全局记录只读；系统管理员不受限。公告不改变业务转发或计费状态，只是运营信息，因此与 schema/恢复日志保持解耦。

## 0.27.0：钱包与订单

钱包、流水、订单和套餐保存在 metadata。资金操作在一个 SQLite 事务内更新余额、写一条唯一引用的流水并推进订单状态；唯一引用索引是重复回调/重试的防线。订单保存套餐价格快照，避免改价追溯。当前商业记录与转发权益解耦：支付成功不会自动生成规则或订阅，这是明确未完成边界。

## 0.28.0：外部支付回调

支付意图与订单分离：创建意图不改变订单；网关回调必须对原始字节通过 HMAC-SHA256 验证，再在事务中把支付意图和订单从 pending 推进到 paid/failed。重复同状态是幂等读取，不重复推进；钱包支付会先把同订单仍待支付的外部意图标记失败，随后到达的外部成功回调会被拒绝，避免两个支付通道同时结算。外部支付不写钱包流水，退款也留在网关侧。

## 0.29.0：工单

工单和消息分键存储在 metadata。读取时按所有者、租户管理员、系统管理员过滤，并对非管理员剔除内部备注；关闭状态在写入消息前检查，避免竞态下给已关闭工单追加消息。消息、状态和审计在同一事务中提交。

## 0.30.0：优惠码

优惠码按唯一代码索引存储，创建订单时在事务内完成有效性、窗口、最低原价、次数和折扣校验，并递增已用次数；订单保存原价、折扣、代码和最终金额。百分比折扣使用整数分向下取整，固定折扣截断到原价，避免负数或超额。优惠码使用在订单创建时发生，未支付订单也会占用次数，这是明确边界。

## 0.31.0：礼品码

礼品码与钱包流水共用事务：兑换时校验启用/窗口/次数，写入余额和唯一引用 `gift:<CODE>:<user>` 的 `credit` 流水，并递增兑换计数。唯一引用同时提供每用户一次和请求重试幂等；已兑换的码只能停用，避免抹掉审计记录。

## 0.32.0：HTTP CONNECT

HTTP CONNECT 在入口 TLS/WS/PROXY 之后解析 HTTP/1.x 请求行与 Basic 认证，目标连接成功后才写 200；失败写 502，方法和认证错误分别写 405/407。解析只接受 CONNECT authority，不实现普通 HTTP 正向代理的 absolute-form 请求，避免把代理入口误当成完整 HTTP 服务。

## 0.34.0：目的地 ACL

规则编译时把目的地模式解析为强类型策略，避免每次连接解析字符串。Engine 在解析目标后、拨号/转发前同时检查原始主机名和解析出的全部地址；拒绝优先，允许列表为空表示全通。代理入口和多路径/预热路径共用同一检查，防止从旁路绕过。

## 0.47.0：模板 canary

模板批量应用按输入顺序分批，每批内逐节点调用现有应用路径，保留每节点修订检查；批次失败停止后续批次，不做隐式回滚。控制器只返回逐节点结果，节点实际激活仍以应用回执为准。

## 0.46.0：稳定化边界

0.46.0 把 SOCKS5 UDP 从共享 IP 注册表改为每控制连接一个临时中继 socket，并按关联首个源端点、已发送目标地址过滤；控制 EOF 取消并等待关联。目的地解析改为逐地址 ACL 过滤。BIND 保留请求对端并执行来源/目的地/私网策略。失败配置激活时，用户份额使用新份额覆盖、旧活动 owner 续租的合并策略。

## 0.45.0：SOCKS5 BIND

BIND 在控制连接所在的本机地址绑定临时 TCP 端口，两次成功回复后把入站连接与控制连接接入同一条计量转发路径。接受入站受连接超时和规则取消约束；当前入站来源不等同于规则来源 ACL，需后续补充。

## 0.35.0：SOCKS5 UDP ASSOCIATE

UDP 关联由 TCP 控制连接注册到每条规则的 UdpRegistry，UDP listener 以客户端 IP 查找关联并解析 SOCKS5 UDP 头。目标仍走统一的 resolver、目的地 ACL、私网策略和出口绑定；回复由中继 listener 发送，保持客户端看到的中继地址。每个数据报当前独立建出口 socket，后续再优化为按目标复用。

## 0.36.0：SOCKS5 UDP socket 复用

UDP 关联首次收到数据报时创建 IPv4/IPv6 出口 socket，并为每个 socket 启动常驻响应任务；后续数据报复用 socket 发送，回复任务统一包装来源地址。关联取消时响应任务与发送循环同时退出。这个改动消除了每包建 socket 的系统调用开销，但尚未按目标做连接缓存或背压。

## 0.41.0：模板预览

预览复用模板克隆与配置校验，但不发布修订；返回拟创建规则和 `valid/error`，让监听冲突、引用错误在写入前可见。它不改变节点配置、运行规则或回执状态。

## 0.38.0：规则模板

模板保存在 metadata，内容是一份已校验的 Rule。应用时在控制器侧克隆规则并重写身份字段，再调用现有配置发布路径；因此监听冲突、引用、端口段和修订冲突仍由同一套校验处理，不会绕过节点配置屏障。

## 0.40.0：MPTCP 能力边界

MPTCP 诊断只读探测内核和 `/proc`，不创建监听、不修改路由、不把普通 TCP 连接标记为 MPTCP。Linux 的 socket 能力、接口、路由和端点作为独立观测返回；非 Linux 明确返回不支持，避免用一个开关伪装聚合成功。

## 0.44.0：UPnP IGD

UPnP 是独立 CLI 管理路径：抓取 description，定位 WANIPConnection/WANPPPConnection 的 controlURL，发送 SOAP Add/DeletePortMapping；不实现 SSDP、不改变监听或转发状态。解析只接受这两个已知服务名，避免引入通用 XML 解析器。

## 0.43.0：PCP MAP

PCP MAP 是另一个独立 CLI 客户端：构造 60 字节请求、随机 nonce、等待 60 字节响应并验证版本/opcode/结果/nonce/协议；不进入转发数据路径。源端口为临时端口，真实网关若强制 5351 仍需后续适配。

## 0.42.0：NAT-PMP

NAT-PMP 是独立 CLI 客户端，不进入转发数据路径：它绑定临时 UDP socket，向网关发送 12 字节映射请求，解析 16 字节响应并输出映射；删除使用生命周期 0。REST API、规则和节点状态不依赖它。
